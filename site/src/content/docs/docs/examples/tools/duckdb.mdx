The DuckDB command line reads the store's Parquet files straight over HTTPS. It fetches only the parts of each file a query needs, so a query on one station of `stations.parquet` doesn't download the whole file. The [Query the store](/query/) page runs the same SQL in your browser.

## Install

```sh
brew install duckdb
```

The [DuckDB install page](https://duckdb.org/docs/installation/) has packages for Linux and Windows. DuckDB loads its `httpfs` extension the first time a query reads an `https://` path, so the first query needs internet access to download it.

Start a session and set it to UTC before reading times:

```sql
SET TimeZone = 'UTC';
```

## Read the station list

[`stations.parquet`](/docs/reference/stations/) has one row per station. Active stations with observed levels:

```sql
SELECT id, name, lat, lon, datum, datums
FROM 'https://stillwell.openwaters.io/stations.parquet'
WHERE status = 'active' AND list_contains(products, 'levels');
```

## Find a station

```sql
SELECT id, name, datum, datums
FROM 'https://stillwell.openwaters.io/stations.parquet'
WHERE name ILIKE '%hoek van holland%' AND source = 'rws';
```

## Read a year of levels

Each station's observed levels are one file per year at `obs/<source>/<source_id>/<year>.parquet`. `flag <= 2` leaves out values flagged as suspect or bad:

```sql
SELECT time, level_m
FROM 'https://stillwell.openwaters.io/obs/rws/hoekvanholland/2024.parquet'
WHERE flag <= 2
ORDER BY time;
```

```
┌──────────────────────────┬─────────┐
│           time           │ level_m │
│ timestamp with time zone │  float  │
├──────────────────────────┼─────────┤
│ 2024-01-01 00:00:00+00   │    0.07 │
│ 2024-01-01 00:10:00+00   │    0.07 │
│ 2024-01-01 00:20:00+00   │    0.07 │
│            ·             │      ·  │
```

To keep a copy, write it to a file:

```sql
COPY (
  SELECT time, level_m, flag
  FROM 'https://stillwell.openwaters.io/obs/rws/hoekvanholland/2024.parquet'
  WHERE flag <= 2
) TO 'hoekvanholland-2024.csv';
```

## Read several years

HTTPS has no directory listing, so a wildcard such as `obs/rws/hoekvanholland/*.parquet` doesn't work, and a missing file is an error. Build the list of files from [`stations/years/<source>.parquet`](/docs/reference/series/#which-years-a-station-has), which has a row for every year file that exists, then pass it to `read_parquet`:

```sql
SET VARIABLE files = (
  SELECT list('https://stillwell.openwaters.io/obs/rws/hoekvanholland/' || year || '.parquet' ORDER BY year)
  FROM 'https://stillwell.openwaters.io/stations/years/rws.parquet'
  WHERE id = 'rws/hoekvanholland' AND epoch = 1 AND year BETWEEN 2020 AND 2024
);

SELECT year(time) AS year, count(*) AS n, round(avg(level_m), 3) AS mean_m
FROM read_parquet(getvariable('files'), union_by_name = true)
WHERE flag <= 2
GROUP BY year ORDER BY year;
```

```
┌───────┬───────┬────────┐
│ year  │   n   │ mean_m │
│ int64 │ int64 │ double │
├───────┼───────┼────────┤
│  2020 │ 52665 │  0.136 │
│  2021 │ 52518 │  0.128 │
│  2022 │ 52533 │  0.135 │
│  2023 │ 52482 │  0.194 │
│  2024 │ 52631 │  0.206 │
└───────┴───────┴────────┘
```

`union_by_name = true` lets files with different columns read together, since some older files lack `source_flag`. `epoch = 1` keeps to the station's plain path; a station whose source moved it to another reference has later files under `obs/<source>/<source_id>/<epoch>/`, as [Datum epochs](/docs/reference/datums/#datum-epochs) describes.

The path holds the station's `source_id` URL-encoded twice: an `@` is `%2540` in the path. Only one station in the store has a character that needs it. [File paths](/docs/getting-started/#file-paths) has the rule. DuckDB's `url_encode` builds it:

```sql
SELECT 'https://stillwell.openwaters.io/obs/' || source || '/' || url_encode(url_encode(source_id)) AS dir
FROM 'https://stillwell.openwaters.io/stations.parquet'
WHERE id = 'gesla/byu_queue_de_tortue_@_riceville_la-8012300-usa-usgs';
```

## Convert to another datum

`datums` maps each datum the station has an offset to, in meters, to add to a level in its own `datum`. Hoek van Holland's levels are in NAP; adding `datums['LAT']` refers them to LAT:

```sql
SELECT o.time, round(o.level_m + s.datums['LAT'], 3) AS level_m
FROM 'https://stillwell.openwaters.io/obs/rws/hoekvanholland/2024.parquet' o,
  (SELECT datums FROM 'https://stillwell.openwaters.io/stations.parquet' WHERE id = 'rws/hoekvanholland') s
WHERE o.flag <= 2
ORDER BY o.time;
```

`datums` describes the station's current epoch. [Converting a level](/docs/reference/datums/#converting-a-level) covers earlier epochs, and [Credits](/docs/reference/datums/#credits) the credits owed for offsets that don't come from the source.

## Things to know

- Times are UTC, as `TIMESTAMPTZ`. Without `SET TimeZone = 'UTC'`, DuckDB shows them in your computer's time zone.
- Levels are meters, in the `datum` column of the same file.
- `level_m` is a 32-bit float. Arithmetic with a 64-bit offset shows the float's error, such as `1.0730000002980231`; round the result to 3 places.
- Select only the columns you need. DuckDB then reads only those columns' bytes from each file.
- [Series](/docs/reference/series/) describes every column and product, including extremes and predictions.
