Every file is under `https://stillwell.openwaters.io/`, readable over HTTPS without an account. The store also holds files its ingest keeps for itself, such as `stations/bounds/`, which aren't described here.

## Water levels

- [Observations](/docs/reference/observations/#observed-levels): `obs/<source>/<station>/<year>.parquet`, one file per station per UTC year.
- [Observed extremes](/docs/reference/observations/#observed-extremes): `extremes/<source>/<station>/<year>.parquet`, the source's high and low waters.
- [Recent days](/docs/reference/observations/#the-latest-values): `recent/<source>/<YYYY-MM-DD>.parquet`, every live station of a source for one UTC day, with today's rewritten every hour.
- [Predictions](/docs/reference/predictions/#predicted-curve): `predictions/<source>/<station>/<year>.parquet`, the source's predicted curve.
- [Predicted extremes](/docs/reference/predictions/#predicted-extremes): `predicted-extremes/<source>/<station>/<year>.parquet`, the source's predicted high and low waters.

## Stations and sources

- [`stations.parquet`](/docs/reference/stations/): one row per station.
- [`sources.json`](/docs/reference/sources/): each source's license, credit, contact and terms.
- [`errata.json`](/docs/reference/errata/): errors found in what sources publish, and what the store does about each.
- [`stations/offsets.parquet`](/docs/reference/offsets/): the meters to add to a level in each station's datum epoch to refer it to each datum.
- [`stations/links.parquet`](/docs/reference/links/): offsets measured each month between the levels of linked stations.
- [`stations/years/<source>.parquet`](/docs/reference/observations/#which-years-exist): every year file of observed levels, with its count of values by flag.
- [`stations/<source>.parquet`](#source-station-lists): one source's own list of stations.
- [`stations/analysis/<source>.parquet`](#station-analysis): what the store measures from each station's levels.
- [`fits/<source>.parquet`](#harmonic-fits) and [`constituents/<source>.parquet`](#harmonic-fits): the harmonic constants the store fits to each station's levels, and how each fit scored.
- `history/stations/<source>/<time>.parquet` and `.json`: each refresh's previous list of a source's stations, in the layout of its time, and a report of what the refresh changed.

## Reading one station

`stations.parquet`, `stations/offsets.parquet`, `stations/years/<source>.parquet` and `stations/analysis/<source>.parquet` are sorted by station, in row groups of 2,048 rows whose statistics give each group's first and last station. A reader that filters on one station and fetches only the byte ranges it needs, as DuckDB, Polars and hyparquet do, reads the file's footer and the one or two groups holding that station rather than the whole file. `stations/links.parquet` has the same groups sorted by `a`, so only a filter on `a` skips them. The files under `recent/` are sorted by `station` in much larger row groups.

## Machine-readable description

[`datapackage.json`](https://stillwell.openwaters.io/datapackage.json) describes each file but those under `history/` as a resource of a [Frictionless Data Package](https://datapackage.org/): its path, each column's type, whether it can be null and what it means, and how its rows are sorted. The column descriptions on these pages come from it. Besides the standard Table Schema properties, each field has `duckdbType`, the type the files are written with, and `optional` where some files lack the column, such as `source_flag` in older files. A resource whose path has a `<placeholder>` gives one real file as its `path` and the layout as `pattern`. [`sources.schema.json`](https://stillwell.openwaters.io/sources.schema.json) and [`errata.schema.json`](https://stillwell.openwaters.io/errata.schema.json) are the JSON Schemas of the two JSON files.

## Source station lists

`stations/<source>.parquet` is one source's list as the store keeps it between refreshes: every station the source has listed but those withheld at their owner's request, with the source's own fields beside them in `extra`. `stations.parquet` is built from these lists, with the columns worked out across sources added.

## Station analysis

`stations/analysis/<source>.parquet` has a row for each station whose levels the store has measured: whether they carry a tide, the step between values that `stations.parquet` uses as `interval_s` where the source gives none, and the measures behind them.

## Harmonic fits

`fits/<source>.parquet` has a row for each station the store has tried to fit harmonic constants for. A fit reads up to 19 years of final values stamped on a UTC hour, in the station's current datum, and is scored on the year after them, which it didn't read. The row gives the window, the scores and what the fit read, or the reason the station has no constants.

A fit is a measurement, published whatever its size. No row says whether a gauge has enough tide to predict: `mean_range_m`, `variance_explained`, each constituent's `snr` and its yearly scatter are there for a reader to set a threshold with.

<Schema resource="fits" />

`constituents/<source>.parquet` has a row for each candidate constituent of each station with constants. The kept rows are the fit's constants. The others say why they were left out.

Every fit starts from the same candidates in the same priority order: Foreman's 45 astronomical and 24 shallow-water constituents ([Foreman 1977](https://waves-vagues.dfo-mpo.gc.ca/Library/54866.pdf)), then the constituents NOAA's 37 and TICON-4's 50 add. A candidate is kept when the record separates it from every stronger one by the Rayleigh criterion and its signal-to-noise ratio is at least 2. Sa and Ssa are kept when their mean over the yearly fits is at least twice its standard error.

The constants are not tied to one prediction program. Each row gives its constituent's Doodson numbers and speed, phases are Greenwich lags with time in UTC, and `node_corrections` in the fit's row names the nodal corrections the amplitudes and phases were fitted under. A prediction has to apply the same corrections: constants fitted under one family predict slightly differently under another, and for a few constituents, such as M1, by much more.
