`stations/offsets.parquet` gives, for each station and datum epoch, the meters to add to a level in that epoch's files to refer it to each named datum. It's `datums` from `stations.parquet` with each epoch's `to_current` already applied, one row per offset, so a level from any epoch converts with a single join. [Datums](/docs/reference/datums/) describes where the offsets come from and how epochs convert.

## Schema

<Schema
  file="stations/offsets.parquet"
  columns={{
    station: "The station's `id` in `stations.parquet`.",
    epoch:
      "The datum epoch whose levels the offset applies to, its `id` in the station's `epochs`. Epoch 1's files are at the plain path (see [File paths](/docs/getting-started/#file-paths)).",
    datum: "The datum the offset refers levels to, such as `NHN`, `MSL`, `LAT` or `MLLW`.",
    offset_m: "Meters to add to a level in the epoch's files to refer it to `datum`.",
  }}
/>

## Which rows an epoch has

- An epoch that converts to the current one has a row for every datum in the station's current `datums`, its offset there plus the epoch's `to_current`.
- An epoch that doesn't convert (`to_current` null) has rows only for its own frozen offsets, from its `datums` in `epochs`. One with none has no rows.
- A station's own label, such as NAP, STND or the `MSL` RWS measures its offshore platforms from, isn't the datum of that name. It has a row only where it's the station's `chart_datum`, as Kartverket's `CD` is, and only in an epoch that converts. Its offset is the epoch's `to_current`, which is 0 in the current epoch.

A join on a datum the epoch has no row for finds nothing. To read a level in its own epoch's reference, or to put it in the station's current `datum`, use `to_current` from `epochs` instead.

## Terms

The file carries no terms or credits of its own. Join it to `stations.parquet` for each station's `commercial_use`, and show `datums_attribution` beside `attribution` wherever the offsets are shown, since some come from slackwater-database or from another station of the gauge.

## Examples

A station's offsets, with the terms they come under:

<QueryResult
  sql={`SELECT o.epoch, o.datum, o.offset_m, s.datums_source[o.datum] AS source, s.commercial_use
FROM 'https://stillwell.openwaters.io/stations/offsets.parquet' o
JOIN 'https://stillwell.openwaters.io/stations.parquet' s ON s.id = o.station
WHERE o.station = 'pegelonline/5990020'
ORDER BY o.epoch, o.datum`}
/>

The first levels of a year referred to LAT:

<QueryResult
  sql={`SET TimeZone = 'UTC';
SELECT l.time, l.level_m AS level_nap_m, round(l.level_m + o.offset_m, 3) AS level_lat_m
FROM 'https://stillwell.openwaters.io/obs/rws/hoekvanholland/2024.parquet' l
JOIN 'https://stillwell.openwaters.io/stations/offsets.parquet' o
  ON o.station = 'rws/hoekvanholland' AND o.epoch = 1 AND o.datum = 'LAT'
ORDER BY l.time LIMIT 5`}
/>

A station whose earlier epochs don't convert, so they have only their frozen offsets:

<QueryResult
  sql={`SELECT epoch, datum, offset_m
FROM 'https://stillwell.openwaters.io/stations/offsets.parquet'
WHERE station = 'refmar/108'
ORDER BY epoch, datum`}
/>

The datums most stations can be referred to:

<QueryResult
  sql={`SELECT datum, count(DISTINCT station) AS stations
FROM 'https://stillwell.openwaters.io/stations/offsets.parquet'
GROUP BY datum ORDER BY stations DESC LIMIT 10`}
/>
