Stillwell is a set of Parquet and JSON files at `https://stillwell.openwaters.io/`. Anything that reads Parquet over HTTPS can query it directly, without an account and without downloading the whole store, including [DuckDB](/docs/examples/tools/duckdb/), [Python](/docs/examples/tools/python/), [JavaScript](/docs/examples/tools/javascript/) and [R](/docs/examples/tools/r/).

Outside a browser, send a `User-Agent` that names your project and its version and gives a URL or email address where its author can be reached, such as `my-project/1.0 (you@example.org)`. The store answers a request with no `User-Agent`, or with some libraries' default one such as Python's `urllib`, with `403 Forbidden`. The examples show how for each tool that can; Polars sends its own, `polars/<version>`, and has no setting to change it. Browsers send their own and need nothing.

This guide follows one station, Hoek van Holland at the mouth of the Port of Rotterdam, from finding it to comparing this year's water with the last ten.

## Find a station

Every station is a row in `stations.parquet`. Search it by name:

<QueryResult
  sql={`SELECT id, name, products, year(first) AS first, year(last) AS last
FROM 'https://stillwell.openwaters.io/stations.parquet'
WHERE name ILIKE '%hoek van holland%' AND id = preferred
ORDER BY id`}
/>

- `id` names the station everywhere in the store. It's the source's ID, then the station's ID within it: `rws/hoekvanholland` is Rijkswaterstaat's Hoek van Holland gauge.
- `id = preferred` keeps one station from each group of linked stations. Several sources can publish the same gauge, and GESLA also has a copy of Hoek van Holland's record. `preferred` names the one to read for its measured levels; [Stations](/docs/guides/stations/) explains how it's chosen. Leave the filter out to see every copy.
- `products` lists what the station has: measured `levels`, measured high and low waters (`extremes`), and the source's tide `predictions` and `predicted_extremes`.
- `first` and `last` bound its record.

Or find the stations nearest a point. This orders them by an approximate distance in kilometers, which is close enough over a few tens of kilometers:

<QueryResult
  sql={`SELECT id, name, kind, status, round(111.2 * sqrt((lat - 51.98) ^ 2 + ((lon - 4.12) * cos(radians(51.98))) ^ 2), 1) AS km
FROM 'https://stillwell.openwaters.io/stations.parquet'
WHERE id = preferred
ORDER BY km LIMIT 5`}
/>

[`stations.parquet`](/docs/reference/stations/) has much more about each station: its datum and offsets to others, whether it's polled live, whether its levels carry a tide, and the terms its data comes under.

## See which years it has

Measured levels are stored one file per station per year, and a year with no data has no file. The station's source has a years list, `stations/years/<source>.parquet`, with a row for each file and a count of its values by quality flag:

<QueryResult
  sql={`SELECT year, hours, good, preliminary, suspect + bad AS flagged
FROM 'https://stillwell.openwaters.io/stations/years/rws.parquet'
WHERE id = 'rws/hoekvanholland' AND year >= 2020
ORDER BY year`}
/>

`hours` counts the hours with at least one value, so a year of hourly or finer values with fewer than 8,760 (8,784 in a leap year) has gaps. **Good** values are ones the source has checked, and **preliminary** ones it hasn't yet. Most recent data is preliminary. [Quality control](/docs/guides/quality-control/) explains each flag and which to keep.

## Read its levels

A year's file is at `obs/<id>/<year>.parquet`. Read one year, leaving out values flagged suspect or bad:

<QueryResult
  sql={`SET TimeZone = 'UTC';
SELECT time, level_m, flag, datum
FROM 'https://stillwell.openwaters.io/obs/rws/hoekvanholland/2025.parquet'
WHERE flag <= 2
ORDER BY time LIMIT 5`}
/>

These hold for every file in the store:

- **Times are UTC.** Set your session to UTC (`SET TimeZone = 'UTC'`), or DuckDB and pandas show them in your local time zone.
- **Levels are in meters**, measured from the datum named on each row. Hoek van Holland's is NAP, the Dutch national height system. [Refer them to another datum](#refer-levels-to-another-datum) below.
- **`flag <= 2`** keeps every value not flagged suspect or bad, including preliminary ones. That's the right filter for most work.
- **Select only the columns you need.** DuckDB, Polars and other readers that make ranged requests then fetch only those columns.

To read several years, list their files and pass the list to `read_parquet`. The server can't list a folder, so a wildcard such as `obs/rws/hoekvanholland/*.parquet` doesn't work. Build the list from the years list instead, which also means you never ask for a year that doesn't exist:

<QueryResult
  sql={`SET VARIABLE files = (
  SELECT list('https://stillwell.openwaters.io/obs/' || id || '/' || year || '.parquet' ORDER BY year)
  FROM 'https://stillwell.openwaters.io/stations/years/rws.parquet'
  WHERE id = 'rws/hoekvanholland' AND epoch = 1 AND year BETWEEN 2021 AND 2025
);
SELECT year(time) AS year, count(*) AS "values", round(avg(level_m), 3) AS mean_m,
  max(level_m) AS highest_m
FROM read_parquet(getvariable('files'), union_by_name = true)
WHERE flag <= 2
GROUP BY ALL ORDER BY year`}
/>

`epoch = 1` keeps to the station's main files. When a source moves a station's zero, its later years go to files of their own; [Building paths in code](#building-paths-in-code) covers that. `union_by_name = true` lets files written before a column was added read alongside newer ones.

## Do something with it

### Refer levels to another datum

A station's `datums` column gives the meters to add to its levels to refer them to other datums, such as mean sea level (`MSL`) or the lowest astronomical tide (`LAT`) that charts measure depth from:

<QueryResult
  sql={`SET TimeZone = 'UTC';
SELECT l.time, l.level_m AS nap_m,
  round(l.level_m + s.datums['MSL'], 3) AS msl_m,
  round(l.level_m + s.datums['LAT'], 3) AS lat_m
FROM 'https://stillwell.openwaters.io/obs/rws/hoekvanholland/2025.parquet' l,
  'https://stillwell.openwaters.io/stations.parquet' s
WHERE s.id = 'rws/hoekvanholland' AND l.flag <= 2
ORDER BY l.time LIMIT 5`}
/>

A level of −0.52 m in NAP is 0.48 m above LAT: there was about half a meter more water than a chart shows. [Datums](/docs/guides/datums/) explains where each offset comes from and how to convert a station whose zero has moved.

### Compare with the tide prediction

Rijkswaterstaat also publishes its tide prediction for Hoek van Holland. The difference between what the gauge measured and what was predicted is mostly weather: wind and air pressure pushing the water up or holding it down. The days of 2025 with the largest surge:

<QueryResult
  sql={`SET TimeZone = 'UTC';
SELECT o.time::DATE AS day, max(o.level_m - p.level_m)::DECIMAL(4, 2) AS surge_m,
  max(o.level_m) AS highest_m
FROM 'https://stillwell.openwaters.io/obs/rws/hoekvanholland/2025.parquet' o
JOIN 'https://stillwell.openwaters.io/predictions/rws/hoekvanholland/2025.parquet' p USING (time)
WHERE o.flag <= 2
GROUP BY day ORDER BY surge_m DESC LIMIT 3`}
/>

The prediction and the measurements must share a datum to compare, as both do here. [Predictions](/docs/reference/predictions/) covers the predicted high and low waters too.

### Compare with earlier years

This year's monthly mean water level against the same months over the ten years before:

<QueryResult
  sql={`SET TimeZone = 'UTC';
SET VARIABLE files = (
  SELECT list('https://stillwell.openwaters.io/obs/' || id || '/' || year || '.parquet' ORDER BY year)
  FROM 'https://stillwell.openwaters.io/stations/years/rws.parquet'
  WHERE id = 'rws/hoekvanholland' AND epoch = 1 AND year >= year(current_date) - 10
);
SELECT month(time) AS month,
  round(avg(level_m) FILTER (year(time) = year(current_date)), 3) AS this_year_m,
  round(avg(level_m) FILTER (year(time) < year(current_date)), 3) AS previous_10_years_m
FROM read_parquet(getvariable('files'), union_by_name = true)
WHERE flag <= 2
GROUP BY ALL ORDER BY month`}
/>

The same pattern works for any station with a long record: change the `id` and the source's years list.

## Building paths in code

A file's path is its product, the station's `id` and the year, as in `obs/rws/hoekvanholland/2025.parquet`. Two things to know when you build one:

- **Station IDs need no encoding.** A `source_id` holds only letters, digits, `.`, `_`, `~` and `-`, so it goes into a path and a URL as it is.
- **Datum epochs.** When a source moves a station to another reference, its later values go to files of their own, with the epoch's number after the station: `obs/<source>/<station>/2/<year>.parquet`. Most stations have one epoch and only the plain path. [Datum epochs](/docs/guides/datums/#datum-epochs) shows how to read across several.
