# How Stillwell quality-controls water levels

This maps every place a stored value's `flag` or `source_flag` is decided or changed, as of `main` at 4caa051e. Every `file:line` reference, including those to docs, is to that commit (`git show 4caa051e:<path>`). At that commit the store code was in `src/lake/` and its tests in `test/lake.test.ts`, which are now `src/store/` and `test/store.test.ts`. It covers observed levels only: extremes, predictions and predicted extremes are never QC'd or errata-flagged (see [Gaps](#gaps-and-inconsistencies-noticed-while-mapping)).

## Flag scheme

- `Flag` is `good 0, interpolated 1, preliminary 2, suspect 3, bad 4` (`src/schema.ts:7-13`). Combining flags is always `Math.max`, so a flag only gets worse within one pass.
- An `Observation` carries `flag`, an optional `source_flag` and an optional `received` (`src/schema.ts:25-29`). Files store `time, level_m, flag, source_flag, received, datum` (`src/lake/parquet.ts:91-119`); `level_m` is a `FLOAT` column (`src/lake/parquet.ts:849`).
- `source_flag` is the source's flag after the adapter's mapping, on the same 0 to 4 scale, never the raw upstream code. It is set in one of three places:
  - `withSourceFlag` (`src/qc.ts:47-54`) sets `source_flag = source_flag ?? flag` on freshly fetched rows and rounds `level` to 0.1 mm (`src/qc.ts:51`), so a fetched value equals its stored copy, which flatline detection depends on.
  - `withErrata`'s `mark` (`src/errata.ts:207-218`) raises `flag` to at least suspect inside a flagged erratum's span and sets `source_flag = source_flag ?? flag` first, so the source's flag survives.
  - Two adapters set it themselves: CRMS (`src/sources/crms/index.ts:249`, equal to `flag`) and GESLA (`src/sources/gesla/index.ts:496-502`, the GESLA flag without the store's datum-jump marks).
- `fromSource` (`src/qc.ts:64-74`) is the only place a flag can get better. It sets `flag = max(source_flag, suspect if inside a span)`. For a row with no `source_flag` (written before the column existed), it takes `flag` as the source's when `flag < suspect`, and otherwise leaves the row's suspect or bad flag alone, since it may be QC's.
- `qc` (`src/qc.ts:83-200`) only worsens flags, through `worsen` (`src/qc.ts:103-105`), and only on the window's own rows, never on `context` rows.
- Readers are told `flag <= 2` keeps everything not flagged as a problem (`docs/data.md:30`).

## Per-value tests

All tests are in `qc` (`src/qc.ts:83-200`). Defaults (`src/qc.ts:85-92`): `limit_m = 20`, `flatline_s = FLATLINE_S = 6 * 3600` (`src/qc.ts:39`), `centimeter_flatline_s = 0`, `spike_m = 0.25`, `outliers = true`, `held = true`. No adapter passes options; stored and recent values get theirs from `qcFor` (below), while `judge` passes its own for the tidal verdict (see [Per-station judgment](#per-station-judgment)), and `limit_m` and `spike_m` are never overridden anywhere.

Setup (`src/qc.ts:95-105`): `out` is the window's rows after `unique`; `all` is `out` plus `context` rows at times `out` doesn't have and with finite levels, sorted and deduplicated. `context` is the neighboring years (backfill, requalify) and takes part in run detection and spike neighbors, but not in the medians and spreads of the limit and outlier rules, and is never returned.

### Repeated times

- Rule: `unique` (`src/qc.ts:223-226`) sorts by time (stable) and keeps the first row of each timestamp in input order; later duplicates are dropped silently.
- Applies to every station. Tested in `test/lake.test.ts:443-456`.

### Limit (bad)

- Rule (`src/qc.ts:107-110`): `bad` when the level is non-finite, or more than `limit_m` (20 m) from the median of the window's own finite levels.
- Rationale (`src/qc.ts:9-13`): relative to the series' median, because NN and NAVD88 put inland gauges hundreds of meters up.
- Applies to every station kind and verdict. The median is over whatever window `qc` gets: a calendar year in backfill and requalify, 7 days in the recent window. Tested in `test/lake.test.ts:426-433`.

### Flatline (suspect)

- Rule (`src/qc.ts:112-125`): a run of consecutive values in `all` with exactly equal `level` (`===`) is suspect when it has at least 4 values (`j - i >= 3`), lasts at least `flatline_s`, and either lasts at least `centimeter_flatline_s` or the series around it is not moving in whole centimeters.
- `wholeCentimeters` (`src/qc.ts:208-220`): counts nonzero changes in the 3 days (`DAY_MS`, `src/qc.ts:202`) before the run's first value and after its last; true when there are at least 24 changes and more than half are whole centimeters (tolerance `1e-6` cm). Fewer than 24 changes count as finer than centimeters, so the plain `flatline_s` limit applies.
- With the default `centimeter_flatline_s = 0`, the second condition always holds, so only `flatline_s` matters.
- Rationale: `src/qc.ts:14-21`, and `qcFor`'s comment (`src/lake/recent.ts:799-816`): rivers and lakes sit still for days; a whole-centimeter series can hold one value for hours on a calm day; a gauge's resolution can change mid-year, so resolution is judged locally.
- Effective limits by station (from `qcFor`, below): tidal 6 h; tidal with `tide_m < 0.3` and whole-centimeter values 48 h; still coastal 6 h, or 48 h where values move in whole centimeters; still river, lake, estuary or unset kind 48 h.
- Run detection does not look at time gaps: consecutive values in `all` with the same level form one run however far apart they are. Context years let a run across New Year be judged whole (`test/requalify.test.ts:84-101`).

### Spike (suspect)

- Rule (`src/qc.ts:127-147`): `spacing` is the median step between the window's own rows. For each value in `all`, its residual is its level minus the median of the values within `3 * spacing` before and after it (both sides required, so a slope at an edge or a gap isn't a spike). Threshold is `max(spike_m, 8 * mad(own residuals))`, with `mad` scaled by 1.4826 (`src/qc.ts:236-240`). A value whose residual exceeds the threshold is suspect.
- Rationale (`src/qc.ts:127-129`): noisy gauges get more room, never less than 0.25 m.
- Applies to every station; no option turns it off.

### Held readings (suspect)

- Rule (`src/qc.ts:149-186`): a run of 3 or more values (`j - i >= 2`) each within 1 cm of the run's first value (compared in 0.1 mm units, `<= 100`, `src/qc.ts:163-164`), shorter than `flatline_s`, is suspect when the median of the values within `3 * spacing` before it and the median of those within `3 * spacing` after it are both further than the spike threshold from the run's median, on the same side.
- A run that reaches `flatline_s` is skipped whole and left to the flatline rule (`src/qc.ts:168-172`).
- Rationale (`src/qc.ts:149-155`): a gauge holding a reading while the tide moves; the spike rule only sees such a run's ends. The comment notes that a real level that rises and falls back the same way, such as a lock basin's, is flagged too.
- Controlled by `held`; off for still water (`qcFor`). Tested in `test/lake.test.ts:334-414` (including Wangerooge's held high water and a two-value high water left alone).
- Version: this rule is `RULES = "held-1"` (`src/lake/analysis.ts:65`).

### Outliers (suspect)

- Rule (`src/qc.ts:188-197`): suspect when the level is more than `max(10 * mad(levels), 4 * spike_m)` from the median of the window's own levels, so the floor is 1.0 m.
- Rationale (`src/qc.ts:24-29`, `src/qc.ts:188-189`): a sensor reading its zero; off where regulated pools sit flat for months and then rise meters.
- Controlled by `outliers`; off for still water and for tidal rivers and lakes (`qcFor`). Uses own rows only, so the window is a year in backfill and requalify and 7 days in the recent window.

### `qcFor`: the options per station

`qcFor` (`src/lake/recent.ts:818-828`) gives the QC options for every stored and recent value, the same for every source; only `judge` passes others (`src/lake/analysis.ts:121`, `:134-138`):

| Station                                                                   | Options                                                    | Effect                                                           |
| ------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| Still (`tidal` false), `kind` coastal                                     | `centimeter_flatline_s: 48h, outliers: false, held: false` | flatline 6 h, or 48 h in whole centimeters; no outliers, no held |
| Still, any other kind                                                     | `flatline_s: 48h, outliers: false, held: false`            | flatline 48 h; no outliers, no held                              |
| No verdict (`tidal` null), river or lake                                  | same as still, other kind                                  |                                                                  |
| Tidal, or no verdict and any kind but river or lake                       | `{}`                                                       | flatline 6 h, outliers and held on                               |
| Tidal with `tide_m < CENTIMETER_TIDE_M` (0.3 m, `src/lake/recent.ts:797`) | adds `centimeter_flatline_s: 48h`                          | 48 h where values move in whole centimeters                      |
| Tidal river or lake                                                       | adds `outliers: false`                                     |                                                                  |

Rationale is the comment at `src/lake/recent.ts:799-816`. Tested in `test/analysis.test.ts:130-155`. The station's `tidal` and `tide_m` come from the analysis file, merged into every list ingest reads by `listOf` → `withAnalysis` (`src/refresh.ts:317-341`, `src/lake/analysis.ts:214-224`).

## Per-station judgment

`judge` (`src/lake/analysis.ts:110-155`) decides `tidal`; `analyze` (`src/lake/analysis.ts:243-351`) runs it and stores the result in `stations/analysis/<source>.parquet`.

- Input: the current epoch's year files for the year of the station's last value and the year before (`src/lake/analysis.ts:288-294`), plus suspect spans from the source's `suspect` over the epoch's whole record (`src/lake/analysis.ts:296-312`). Only GESLA defines an adapter `suspect`; every other source gets only its `errata.json` spans through `withErrata` (`src/errata.ts:222-233`).
- Flags start over: rows with no `source_flag` and a flag of suspect or worse are dropped, then `fromSource` with the spans (`src/lake/analysis.ts:115-119`).
- `still` = `qc(start, { flatline_s: 48h, outliers: false, held: false })` (`src/lake/analysis.ts:121`).
- `tide_m` = `tideOf` on `still` (`src/tidal.ts:20-38`): M2 plus O1 amplitude from a harmonic fit over the last 366 days of values with `flag < suspect`; null when they span under 30 days or their median step exceeds 3 h.
- `tide` = `qc(start, {...})` with `qcFor({ tidal: true, tide_m })` for rivers and lakes and `{}` otherwise, both with outliers and held off (`src/lake/analysis.ts:133-138`).
- `drains` (`src/tidal.ts:49-60`): runs of consecutive values within 366 days of the last usable value that `tide` flags suspect and `still` doesn't.
- `days`: distinct UTC days with usable values in that year (`src/lake/analysis.ts:139-143`).
- Verdict (`src/lake/analysis.ts:145-154`): null when `tide_m` is null or `days < COVERED_DAYS` (30, `src/lake/analysis.ts:75`). Otherwise tidal when `tide_m >= TIDE_M` (0.08 m, `src/tidal.ts:7`), and not `aboveSea`, and (`kind` is coastal or `drains <= DRAINS_RUNS` (3, `src/tidal.ts:10`)). `aboveSea` is the median usable level plus `toSeaLevel` above `ABOVE_SEA_M` (10 m, `src/lake/analysis.ts:83`); `toSeaLevel` (`src/lake/analysis.ts:184-188`) is 0 where the station datum is in `SEA_LEVEL` (`src/lake/analysis.ts:163-177`), the datum offset where `datums` has one, and null otherwise (then `aboveSea` is false).
- Versions: `RULES = "held-1"` (`src/lake/analysis.ts:65`) must change with any rule in `src/qc.ts` or threshold in `qcFor`; `JUDGE = "drains-2"` (`src/lake/analysis.ts:72`) with any verdict rule. Nothing enforces either bump.
- Due (`src/lake/analysis.ts:253-264`): station has a last value in the bounds and (`--all`, no row, other `RULES`, other `JUDGE`, `tidal` null, or judged more than `REJUDGE_MS` = 365 days ago, `src/lake/analysis.ts:89`).
- A null verdict never replaces a non-null one; under new `RULES` the old verdict is kept and marked for requalify (`src/lake/analysis.ts:318-323`).
- What the verdict changes: only `qcFor`'s options. `changed` compares `qcFor` before and after (`src/lake/analysis.ts:325-328`). `requalified` is set to null (pending) when the options changed, on a first verdict, or under new `RULES` (`src/lake/analysis.ts:330-338`). Changes go to `history/analysis/<source>/<time>.json` (`src/lake/analysis.ts:275-282`).
- `publish` puts `tidal` and `tide_m` into `stations.parquet` (`docs/data.md:49-50`).

How preliminary values become final:

- `finalizes` (per adapter metadata) puts a source in the monthly refetch (`src/sources/jobs.ts:38`). The refetch starts from the earliest value with `coalesce(source_flag, flag) = 2` (`src/lake/parquet.ts:307,753`), no earlier than January three years back (`REFETCH_YEARS = 3`, `src/lake/recent.ts:475`), and per-source arguments in `.github/workflows/monthly.yml:226-268`.
- `yearDone` (`src/backfill.ts:72-82`) refetches an ended year while its file holds any value whose source flag is preliminary, unless the year ends by `source_qc_start`.
- Compaction's `upsert` (`src/lake/merge.ts:80-102`) never lets a value whose source flag is worse than interpolated replace a stored one whose source flag is good or interpolated. Revisions of finalized values arrive only through backfill, which replaces what it fetched (`mergeFetched`, `src/lake/merge.ts:36-50`).

## Errata

- Schema and validation: `src/errata.ts:28-142`. `handling` is one of `corrected`, `flagged`, `dropped`, `refused`, `avoided`, `kept` (`src/errata.ts:18-25`). `since`/`until` are UTC days, `until` exclusive.
- Only `flagged` entries with a span change flags in code: `spans` (`src/errata.ts:184-196`) returns `[since, until)` for each flagged entry naming the station (or every station) with at least one end set; an open end is infinite.
- `withErrata` (`src/errata.ts:204-247`) wraps each source in the registry: it marks the levels `observations` and `recent` return (suspect, keeping `source_flag`), and appends the spans to the source's `suspect`, which recent, requalify and analysis apply to stored values through `fromSource`. When the adapter's `suspect` throws `Unjudged`, the errata spans are added to the error's spans (`src/errata.ts:226-230`).
- Every other handling is adapter code that cites the erratum ID: clock shifts (`gesla-wsv-hourly-means-early`, `gesla-hong-kong-hour-early`, `gesla-crms-hour-early`, `uhslc-hong-kong-hour-early`), a day stamp (`jma-saigo-1980-day-stamp`), CO-OPS's stale limit flag (`coops-stale-limit-flag`, which changes `flagOf`), position fixes, dropped stations or records (`gesla-uddevalla-is-arko`, `usace-placeholder-positions`), and a refused file (`dwr-b95580-another-header`, B95580's file, which names another station).
- GESLA's datum jumps (`gesla-datum-jumps`) are a flagged erratum with no span; the adapter works them out from the whole record (`src/sources/gesla/index.ts:811-839`, `JUMP_M = 0.75` m) and throws `Unjudged` when the store holds less than the record's stated ends with a year's margin.
- Counts by source (flagged, all): BODC 1/4, CO-OPS 7/8, DWR 0/1, EA 3/3, GESLA 15/22, JMA 0/1, Marine Institute 6/8, PEGELONLINE 9/13, REFMAR 4/7, RWS 0/2, SFWMD 2/2, SMHI 1/1, UHSLC 7/12, USACE 0/6.
- Applying a new or retired flagged span to stored values needs a `requalify` run over its years (`CONTRIBUTING.md:229`); nothing schedules it.

## Cross-station checks

- Library `src/cross-check.ts`, runner `scripts/cross-check.ts`. They only report: the script writes Markdown to stdout and a local cache, and changes nothing in the store (`scripts/cross-check.ts:1-11`). Findings become errata by hand (`CONTRIBUTING.md:183-198`).
- Input (`scripts/cross-check.ts:166-215`): per hour, the value within 10 minutes of the hour with `flag IN (0, 2)`; stations with `kind` river or lake are left out (`:112`); only epoch 1 is read (`seriesPath` default, `:198`); `same_as` groups count as one gauge, the `preferred` one.
- Copied months (`monthlyAgreement`, `copies`, `src/cross-check.ts:33-96`): monthly correlation and RMS after removing the mean difference, months with at least 360 shared hours; a month counts when RMS `< 0.03` m and `< 0.25 *` the pair's median RMS, after at least 6 months; pairs usually within 0.03 m must match within 0.002 m; pairs usually under `SAME_GAUGE` (0.01 m) are reported as missing `same_as` links.
- Tide timing (`timing`, `src/cross-check.ts:118-176`): 15-day windows, at least 240 hours, least-squares lag in the semidiurnal (26 to 32 °/h) and diurnal (12 to 17 °/h) bands against a fit of up to 40 standard constituents without long-period ones; diurnal only when its RMS is at least 0.05/√2 m. Reported runs depart from the station's median by `max(LATE_MIN 8 min, SIGMAS 4 × scatter)`; stations with fewer than 6 windows or scatter over `MAX_SCATTER` 20 min are skipped (`scripts/cross-check.ts:47-55,300-345`).
- Level steps (`dailyMeans`, `steps`, `attribute`, `src/cross-check.ts:221-362`): daily means from 20 or more hours, station minus each of its `NEIGHBORS` 4 nearest within `NEIGHBOR_KM` 150 km; a step is where the medians of 30 daily values either side (spanning at most 120 days) differ by 0.08 m or more and by 3 times the spread; it counts for the station when at least 2 neighbors show it within 5 days with the same sign and more do than don't.
- Runs monthly, after a full station refresh, over the current year and the five before, in three regions: German Bight (PEGELONLINE, GESLA), US East Coast (CO-OPS, GESLA), Sweden (SMHI, GESLA) (`.github/workflows/monthly.yml:285-321`).

## Linking and datum epochs

- `same_as` (`src/same-as.ts`) changes no flag. Flags feed into it: `rank` weighs a record's span by its share of values with flag 0 to 2 (`src/same-as.ts:364-395`, `usableShares` in `src/lake/years.ts:98-112`), so heavily flagged records lose `preferred`.
- Datum epochs (`src/epochs.ts`) change no flag. They bound every QC window: each epoch has its own year files; requalify works each epoch's files separately with context only from the same epoch (`src/lake/requalify.ts:35-99`); analysis reads only the current epoch (`src/lake/analysis.ts:288`); the recent window QCs only the current epoch's rows and passes older epochs' rows through untouched (`src/lake/recent.ts:200-201`); a station with a held epoch isn't fetched or QC'd (`src/lake/recent.ts:202-205`).

## Efficiency notes

- `qc` cost: the spike pass computes a median of up to about 6 neighbors per value; the held pass does a slice median and two side medians per starting index (`src/qc.ts:165-186`); `mad` and `median` sort full arrays (`src/qc.ts:228-240`). Roughly O(n log n) per window; at 6-minute data a year is about 88,000 values, plus up to two context years.
- `recent`: every hour re-reads the source's recent file in batches of 500 stations (`BATCH`, `src/lake/recent.ts:49`), re-QCs each station's full 7-day window, and rewrites the whole file. Each value is QC'd about 168 times before it ages out.
- `compact`: reads and rewrites a whole year file per station whenever its last 6 days changed, without QC. With `--days 6`, each day is folded up to 6 times.
- `backfill`: `seriesFiles` (`src/backfill.ts:398-427`) holds at most three year files, so a walk reads each year once and its context comes from the cache. Each fetched year is QC'd against its full year plus neighbors.
- `requalify`: reads each wanted file's datums first (`src/lake/requalify.ts:41-45`), then reads every year once more through a three-year cache (`:69-86`). For GESLA, `suspect` also reads every year of the epoch (`:52-55`). Called from `analyze --requalify`, it covers the whole record of every pending station. Writes only changed files.
- `analyze`: reads two year files per due station (`src/lake/analysis.ts:291-294`), runs `qc` twice and a harmonic fit. For GESLA, `suspect` reads the whole epoch (`:301-305`). Stations with a null verdict are due every month (`:261`), so they are read and fit every month.
- A `RULES` bump marks every station pending (`src/lake/analysis.ts:330`), so every year file of the source is read and possibly rewritten, limited to 120 minutes of batch starts per source per month.
- Cross-check: per station and year, a DuckDB query over the public bucket (`scripts/cross-check.ts:196-215`); the cache in `.cache/cross-check/` isn't restored between workflow runs (`.github/workflows/monthly.yml:300-321` has no cache step), so each monthly run reads six years for every station in the three regions again.

## Gaps and inconsistencies noticed while mapping

Each is an observation from mapping. The bold status after each is the evaluation's verdict, with the evidence in [evaluation.md](evaluation.md#suspected-gaps).

1. Recent-window QC differs from year QC. The current year's stored flags come from 7-day windows: `limit_m` and outlier medians and spreads, and the spike `mad`, are over 7 days, and compaction folds them in without re-QC (`src/lake/recent.ts:246`, `:405`). A monthly requalify of the current year is then partly overwritten by the next compaction for the last 6 days. `CONTRIBUTING.md:116` acknowledges this. **Confirmed in code; rerunning year QC changed no flag on four 2026 station-years.**
2. A run within 1 cm that isn't exactly flat escapes both rules. The held rule skips a near-level run once it reaches `flatline_s` (`src/qc.ts:168-172`), and the flatline rule needs exact equality (`src/qc.ts:116`). A stuck gauge that dithers by a millimeter or two for hours is not flagged. **Confirmed.**
3. Flatline runs ignore time gaps (`src/qc.ts:114-125`). Four equal values spanning a long data gap count as a 6-hour flatline. Untested. **Confirmed.**
4. `spacing` is one median per window (`src/qc.ts:130`). In a year that mixes sampling intervals, such as hourly then 6-minute, the sparser part may have no neighbors within `3 * spacing` and is never spike- or held-checked. **Confirmed on synthetic input.**
5. The outlier floor is 1.0 m over the window's own levels (`src/qc.ts:193`). In a 7-day recent window at a tidal coastal station with a small tide (outliers on for tidal non-river stations), a storm surge over about 1 m may be flagged suspect hourly and folded in. Worth checking against known surges. **Refuted on real data: no flag in eight microtidal hurricane and river years.**
6. `judge`'s `tide` pass uses plain `{}` for every kind but river and lake (`src/lake/analysis.ts:133-138`), while `qcFor` gives a tidal station with `tide_m < 0.3` the 48-hour whole-centimeter limit. For `estuary` or unset kinds, `drains` may count holds the station's tidal QC would not flag, tipping it to still. **Confirmed, and intended by the comment at `src/lake/analysis.ts:124-132`.**
7. The recent window catches every `suspect` error, not only `Unjudged`, and then keeps stored flags (`src/lake/recent.ts:231-235`); requalify and analysis rethrow other errors (`src/lake/requalify.ts:56-57`, `src/lake/analysis.ts:306-307`). **Confirmed.**
8. Nothing enforces `RULES`/`JUDGE` bumps when `src/qc.ts` or `qcFor` change (`src/lake/analysis.ts:60-72`, `src/lake/recent.ts:794-795`). A rule change without a bump never reaches stored years. **Confirmed.**
9. No dedicated unit test for `wholeCentimeters` thresholds (24 changes, 3 days, more than half whole) or for `limit_m` on non-finite levels; they are exercised only indirectly (`test/analysis.test.ts:89`, `test/requalify.test.ts:331`). There is no `test/qc.test.ts`; `qc` tests live in `test/lake.test.ts:310-457`. **Confirmed.**
10. A source-flagged preliminary value is never refetched: USGS `ICE`/`EQUIP`, CO-OPS F/R on `p`, RWS non-`00` codes, SFWMD unknown codes and others store `source_flag` 3, so `coalesce(source_flag, flag) = 2` (`src/lake/parquet.ts:307,753`) misses them and the verified value never arrives without `--refetch`. `src/backfill.ts:53-60` acknowledges the USGS case. **Partly confirmed: the refetch starts at the earliest preliminary value and refetches everything after it, so only stretches whose unverified values are all source-suspect are missed.**
11. Unmapped codes fall through inconsistently: to 0 for DMI `qcResult` outside 1 to 6 and CO-OPS `q` other than `p`/`v` (`src/sources/coops/index.ts:330`); to 3 for BODC, DWR, Marine Institute, RWS, SFWMD, SMHI, UHSLC; to 2 for USGS non-`Approved` status. Marine Institute and UHSLC compare numbers with `===` (`src/sources/marine-institute/index.ts:203`, `src/sources/uhslc/index.ts:505`), so a string code would make every value suspect. **Confirmed in code; no affected value found.**
12. PEGELONLINE's REST path maps `v.value * scale` with no null filter (`src/sources/pegelonline/index.ts:183`); a null becomes 0 m with flag 2, while the download path filters (`:254`). JMA accepts any integer cell with no sentinel check. **Confirmed in code; the isolated 0.0 m values in PEGELONLINE's recent data are the source's own.**
13. `bad` from adapters comes only from BODC, DMI, GESLA and USACE; elsewhere `bad` comes only from `limit_m`. Sources whose codes mean "erroneous" map to suspect (for example DWR 151 and 255 are dropped, SMHI non-G/O/Y letters 3). **Confirmed.**
14. GESLA treats "no QC" (code 0) as good (`src/sources/gesla/index.ts:439-440`), while every other source treats unchecked values as preliminary. **Confirmed; deliberate.**
15. Extremes, predictions and predicted extremes get no QC and no errata marks (`src/backfill.ts:485-497`; `CONTRIBUTING.md:229` says extremes aren't flagged). Observed extremes from a span that levels flag suspect stay good. **Confirmed.**
16. Backfill judges the fetched year against its neighbors but does not re-QC the neighbors, so a backfill changes the context of years it doesn't rewrite until a requalify (`src/lake/requalify.ts:117-123`, documented in `CONTRIBUTING.md:116`). **Confirmed.**
17. Retiring or adding a flagged erratum needs a manual `requalify` (`CONTRIBUTING.md:229`); nothing schedules or checks it. **Confirmed.**
18. Cross-check reads only epoch 1 (`scripts/cross-check.ts:196-198`), drops interpolated values (`flag IN (0, 2)`, `:206`), leaves out rivers and lakes (`:112`), and its findings change no flag. **Confirmed.**
19. Docs that disagree with code: **Confirmed, with one more item, the last below.**
    - `docs/data.md:30` says stored years are requalified "when someone runs `requalify` after a rule changes"; the Monthly workflow does it automatically through `analyze --requalify` (`.github/workflows/monthly.yml:151`).
    - `docs/data.md:31` says an adapter marks REFMAR's Pointe-à-Pitre span; it is an `errata.json` entry applied by `withErrata` (`src/sources/refmar/errata.json`, `src/errata.ts:204`). `CONTRIBUTING.md:116` calls the same span the adapter's `suspect`.
    - `CONTRIBUTING.md:41` lists the ingest commands without `analyze`; `CONTRIBUTING.md:54` lists nine including it.
    - `docs/data.md:49` describes still water's rules without the held-level check being off; `docs/stations.md:159` has it.
    - The RWS README names only `Gecontroleerd` and `Ongecontroleerd`; the code also treats `Definitief` as checked (`src/sources/rws/index.ts:388`).
    - `src/qc.ts:6` says QC "runs in Node and in the Worker"; only `src/lake/*` imports it, and `workers/` holds only `cron`.
    - `src/qc.ts:44-45` and `src/backfill.ts:59-60` say REFMAR's adapter marks suspect spans and sets `source_flag`; REFMAR defines no `suspect`, and Pointe-à-Pitre is the erratum `refmar-pointe-a-pitre-clock`.
20. Analysis cost: stations with a null verdict are re-read and re-fit every month (`src/lake/analysis.ts:261`), and a `RULES` bump requalifies every station's whole record under a 120-minute budget per source per month (`scripts/ingest.ts:922-944`), so a large source such as USGS may run under mixed rules for several months while recent and backfill already use the new ones. **Confirmed.**
21. Level storage is `FLOAT` (`src/lake/parquet.ts:849`) while flatline equality relies on 0.1 mm rounding (`src/qc.ts:48-51`); worth confirming the read-back rounding (`level`, `src/lake/parquet.ts:997`) keeps equal values equal for gauges hundreds of meters above their datum. **Confirmed at six USGS stations whose 2026 levels are 1,087 to 1,817 m, about a fifth of their stored values 0.1 mm off.**
