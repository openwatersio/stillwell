# Sources

## Adding a source

Each source is a directory in [`src/sources/`](../../src/sources) that exports a `Source` (defined in [`src/schema.ts`](../../src/schema.ts)), registered in [`src/sources/index.ts`](../../src/sources/index.ts), with a README. The site shows the README on the source's page, so it opens with what a reader of the data needs: license, contact, which stations are listed, levels, flags, times, datums, history and quirks. Errata are documented only in the source's `errata.json`, which the page lists; the README has no Errata section and doesn't repeat them. Everything about operating the adapter, such as request limits, backfill plans, shards and workflow notes, goes in a last `## Running ingest` section, which the site leaves out; [`test/readme.test.ts`](../../test/readme.test.ts) checks the layout. Its metadata's `contact` says where to report an error in the data: the agency's own mailbox or contact form, never a person's address, with the page that publishes it in the README. Record real responses into [`test/fixtures/`](../../test/fixtures) for its tests rather than calling the service. Check the source's terms before writing anything to the public store. The store republishes the data, so its `license.redistribution` decides the store: a source whose terms bar republishing goes to the restricted store. Commercial use is a separate tag, `commercial_use`, which the API and products filter on per station: the source's default, set per station where the terms differ, such as a contributor's own terms in a source that relays other agencies' data. `sources.json` gives a source's `license.commercial_use` as true only where every station allows it. Data the source itself withholds until its owner grants permission isn't listed at all, and nor is data whose owner refused permission (see [Withheld stations](#withheld-stations)).

A station's `source_id` holds only letters, digits, `.`, `_`, `~` and `-`, so a store path and a URL hold it as it is; a refresh refuses any other. Where the source's own ID has another character, the adapter makes one from it and keeps the original beside it, as GESLA's `file` does.

Registering the source is all the scheduled workflows need. Each picks its sources from the adapters' metadata ([`src/sources/jobs.ts`](../../src/sources/jobs.ts), printed by `node scripts/sources.ts <job>`), so none lists them by hand:

- hourly ingest takes the sources whose metadata sets `hourly`, meaning they publish values within hours;
- nightly compaction takes every source with `observations`, and every hourly one;
- the Monthly workflow refreshes every source's list, then runs the backfills its `schedule.lists` returns, for a source that nothing else fetches, such as one with only predictions;
- the monthly refetch takes the sources whose metadata sets `finalizes`, meaning values they publish as preliminary become final later. By default it reads each station from its earliest preliminary value, from January `REFETCH_YEARS` back, to this month. A source whose new or final values that doesn't reach, such as one nothing else fetches or one that reflags old years, returns its own backfills from `schedule.refetch`, with a comment saying why; `node scripts/schedule.ts refetch <source>` prints them.

Only sources whose `license.redistribution` is true are scheduled, since the workflows have no restricted store. The workflows run [`scripts/sources.ts`](../../scripts/sources.ts) without `npm ci`, so nothing an adapter imports may be a package; [`test/jobs.test.ts`](../../test/jobs.test.ts) checks. Until a new source's list is in the store, its hourly and compaction jobs skip it with a note; the Monthly refresh on the 2nd starts the list, or dispatch Monthly with `sources` set to the source after merging to start it at once. The skip shows as a warning on the run's page. A manual refetch of a source with no list yet fails; the scheduled one on the 9th comes after the refresh on the 2nd.

## Source errata

When a source publishes something wrong, such as values on the wrong clock or day, a gauge placed far from where it is, metadata that contradicts the data, or two endpoints that disagree, record it as an erratum, whether the adapter works around it or not. Each source's errata are in `src/sources/<source>/errata.json`, reviewed with the code that handles them; nothing else holds them.

1. Add an entry to the source's `errata.json` (start the file as `{"errata": [], "retired": []}` and import it in `errataFiles` in [`src/sources/index.ts`](../../src/sources/index.ts), which the tests check): an `id` (`<source>-<what>`, never reused), the `stations` it affects (store IDs, or `"every station"`), the UTC days of values it's in (`since`, and `until`, the day after the last; leave one out for an open end, both for an error in metadata), what's wrong (`error`), what the store does about it (`handling`: `corrected`, `flagged`, `dropped`, `refused`, `avoided` or `kept`, and `response`, in a sentence or two), and how it was found (`evidence`). A `flagged` entry with stations and a span needs no code: the adapter registry flags that span `suspect` in the levels the store fetches or requalifies (extremes aren't flagged), keeping the source's own flag as `source_flag`. Run `requalify` over the span after it merges to flag the values already in the store, and again after an entry stops being `flagged`, to clear them, once any epoch or offset that replaces the flag is in the store (after the station refresh that applies it).
2. Cite the ID as ``erratum `<id>` `` where the adapter works around the error otherwise. The tests fail on a file that doesn't parse, an ID used twice or retired, and a citation no entry holds.

`publish` puts each station's errata in the `errata` column of `stations.parquet` and writes them to `errata.json`, with a link to the file each is in, and fails the run, after publishing, on an erratum that names a station the store doesn't hold.

Reports go to each agency in its own language, one message covering its errata not yet reported, to the channel in the adapter's `metadata.contact`, and only once a person has approved the text. `npm run errata` drafts that message for each source with entries that have no `reported` date (`npm run errata -- <source>` for some). An entry with a `report` but no `reported` date is held back, and the note says why. Once it's sent, set each entry's `reported` to the day and its `report` to where it went, naming the channel (the agency's contact form or published address), never a person; add the agency's answer to `report` when it comes. When the agency fixes the data, remove the workaround, refetch what it touched, and delete the entry, moving its ID to `retired`.

Anyone can report an error with the **Source error** issue form. A maintainer who agrees adds the entry and closes the issue.

## Withheld stations

A station whose owner refused permission to republish its data is withheld: never listed, fetched or published, and deleted from the store. A source names them with `withheld` (`Source` in [`src/schema.ts`](../../src/schema.ts)). The rule covers UHSLC's records and GESLA's copies of them: UHSLC withholds every series of a station number one of whose documentation files carries a notice marked `refused` in [`src/sources/uhslc/notices.ts`](../../src/sources/uhslc/notices.ts), versions the scan hasn't read included, and GESLA every copy of such a series and every record carrying such a notice. `ALSO_WITHHELD`, beside the notices, adds station numbers by hand, with the reason, where another source credits the gauge to a refusing contributor. Today that's the South African Navy Hydrographic Office's ([#80](https://github.com/openwatersio/stillwell/issues/80), [#82](https://github.com/openwatersio/stillwell/issues/82)): 27 stations, GESLA's 25 records of its gauges, UHSLC's Walvis Bay, `uhslc/220`, and UHSLC's Lüderitz, `uhslc/702`. Lüderitz's UHSLC documentation names no contributor, but GESLA names SANHO as originator and SANHO refused "any of our national tide gauge data", so `ALSO_WITHHELD` names 702. A refusal from any other contributor, such as one of GESLA's own, needs a rule of its own.

GESLA also withholds a record's ID from before IDs had to be URL-safe, once it lists the record under a URL-safe one. Such a move starts the new ID empty: run `ingest withhold gesla` to delete the old ID's files, then refresh the list, backfill the new ID and publish.

An adapter refuses to fetch a withheld station, and `backfill`, `recent`, `compact` and `requalify` read the source's list without them, so a list not yet refreshed fetches nothing of theirs. Each refresh drops them from the list it read, from the snapshot it writes of that list, and from the source's bounds, recent window, empty-years record, backfilled years, requalify list and analysis, with its history, reporting them as removed rather than retired, and leaves them out of the sharp-shrink guard. It refuses to remove more than 5 stations or 2% of the list, whichever is larger, as likelier a wrong rule; `--accept-withheld`, the Monthly workflow's `accept_withheld`, lets that through once a person has checked the rule. While any withheld station the store has known, by the list, its history, the bounds, the recent window or the analysis, still has series files, every refresh's report says to run `withhold`, and the run fails, after writing the list; in the Monthly workflow, the publish job still runs after a failed list job, so `stations.parquet` drops the station either way. `publish` leaves out any the list still has, and doesn't count an erratum naming a withheld station as naming an unknown one. `withhold` deletes their files:

```bash
node scripts/ingest.ts withhold gesla
```

It finds every withheld station the store has known, from the source's list, its history, its bounds, its recent window and the directories of its files, and refuses more than the refresh's limit of those stations unless `--accept-withheld`. Then it deletes each one's directory under `obs/`, `extremes/`, `predictions/` and `predicted-extremes/`, later epochs included, and drops its rows as a refresh does. A local store's are deleted from disk; on R2 the AWS CLI deletes them with the store's `S3_*` credentials, since DuckDB can't delete objects, and refuses any other remote store, such as the public one over HTTPS. Each prefix ends in the station's encoded ID and a slash, so it names that station's directory alone, and an empty ID, `.` or `..` is refused.

To withhold stations in the R2 store once the change is on `main`:

1. Check in Actions that no Ingest, Ingest hourly, Compact daily or Monthly run for those sources, started from `main` before the merge, is still queued or running. Such a run uses the old code, which lists and fetches the withheld stations and could write their files back after `withhold` deletes them.
2. Dispatch Ingest with `withhold <source>` for each source the rule covers, such as `withhold gesla`, then `withhold uhslc`. Each runs in the source's group, so check that it started rather than show as cancelled.
3. Dispatch Monthly with `sources` set to those sources, `gesla uhslc`, which drops them from the lists and publishes `stations.parquet`.
4. Run `npm run ticon:inventory` against the refreshed public store and commit the [TICON inventory](../ticon-inventory.md) and its CSV, so GESLA's copies of withheld records are no longer named.
5. Take withheld stations out of the errata that list them, such as Mossel Bay's FD record in `gesla-uhslc-positions`. `publish` doesn't fail on them meanwhile.

The other order works for steps 2 and 3, since `withhold` finds stations the list no longer has, but this one deletes the values first. Rolling back the release that withholds them would list them again at the next refresh and fetch them again at the next backfill, so a rollback needs these steps repeated once the rule is back. Snapshots in `history/stations/` written before the refresh still list the withheld stations, without any values; neither command rewrites them.

A GESLA record whose values are another gauge's (`isDropped` in [the dropped-records list](../../src/sources/gesla/dropped.ts)) stays in the list, inactive with no products, but its stored files aren't deleted by a refresh or by `withhold`. `drop` deletes them, for the records whose files the source's rule names (`deletesFiles`), and only those with files; `--dry-run` lists them and deletes nothing. It runs from the Ingest workflow in the source's group. It drops their rows from the years file and the analysis as well, and the backfilled years of every record the rule names, with files or not, which `--dry-run` counts by station; afterwards `compact <source> --rebuild-bounds` and `publish` drop them from the bounds and from `stations.parquet`'s `first` and `last`. Rolling back past the change that drops them lists them as active again, and a `backfill … all` on that build fetches them back:

```bash
node scripts/ingest.ts drop gesla --dry-run
```
