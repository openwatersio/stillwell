# Sources

## Adding a source

Each source is a directory in [`src/sources/`](../../src/sources) that exports a `Source` (defined in [`src/schema.ts`](../../src/schema.ts)), registered in [`src/sources/index.ts`](../../src/sources/index.ts), with a README, written as [Source READMEs](#source-readmes) says. Its metadata's `contact` says where to report an error in the data: the agency's own mailbox or contact form, never a person's address, with a comment beside it citing the page that publishes it. Record real responses into [`test/fixtures/`](../../test/fixtures) for its tests rather than calling the service. Check the source's terms before writing anything to the public store. The store republishes the data, so its `license.redistribution` decides the store: a source whose terms bar republishing goes to the restricted store. Commercial use is a separate tag, `commercial_use`, which the API and products filter on per station: the source's default, set per station where the terms differ, such as a contributor's own terms in a source that relays other agencies' data. `sources.json` gives a source's `license.commercial_use` as true only where every station allows it. Data the source itself withholds until its owner grants permission isn't listed at all, and nor is data whose owner refused permission (see [Withheld stations](#withheld-stations)).

A station's `source_id` holds only letters, digits, `.`, `_`, `~` and `-`, so a store path and a URL hold it as it is; a refresh refuses any other. Where the source's own ID has another character, the adapter makes one from it and keeps the original beside it, as GESLA's `file` does.

Registering the source is all the scheduled workflows need. Each picks its sources from the adapters' metadata ([`src/sources/jobs.ts`](../../src/sources/jobs.ts), printed by `node scripts/sources.ts <job>`), so none lists them by hand:

- the poller takes the sources whose metadata sets `hourly`, meaning they publish values within hours;
- nightly compaction takes every source with `observations`, and every hourly one;
- the Monthly workflow refreshes every source's list, then runs the backfills its `schedule.lists` returns, for a source that nothing else fetches, such as one with only predictions;
- the monthly refetch takes the sources whose metadata sets `finalizes`, meaning values they publish as preliminary become final later. By default it reads each station from its earliest preliminary value, from January `REFETCH_YEARS` back, to this month. A source whose new or final values that doesn't reach, such as one nothing else fetches or one that reflags old years, returns its own backfills from `schedule.refetch`, with a comment saying why; `node scripts/schedule.ts refetch <source>` prints them.

Only sources whose `license.redistribution` is true are scheduled, since the workflows have no restricted store. The workflows run [`scripts/sources.ts`](../../scripts/sources.ts) without `npm ci`, so nothing an adapter imports may be a package; [`test/jobs.test.ts`](../../test/jobs.test.ts) checks. Until a new source's list is in the store, the poller and compaction skip it with a note; the Monthly refresh on the 2nd starts the list, or dispatch Monthly with `sources` set to the source after merging to start it at once. The skip shows as a warning on the run's page. A manual refetch of a source with no list yet fails; the scheduled one on the 9th comes after the refresh on the 2nd.

## Source READMEs

The site shows a source's README on its page, after the Terms table and before the values chart, the station table and the errata. The table already gives the license, commercial use, credit, whether the source finalizes preliminary data, how the store changes the data, and where to report errors, from the source's metadata; the page header gives its station counts and first year; the station table gives each station's kind, status and datum; and the errata list every known error. The README says only what those don't, in as few words as it can.

- **Say each fact once.** Leave out the license, credit, terms, contact, station counts, first year and anything else the page shows. A fact the page could show from metadata goes in the metadata.
- **`metadata.terms` holds conditions of use** beyond the license and credit, and is left out where there are none. A note on the data's status, such as "provisional values may be revised", goes in Flags. The changes Stillwell makes to every source's data are stated once, in the `terms` description of the `sources.json` schema ([`src/store/files.ts`](../../src/store/files.ts)). A source's own change goes in the README bullet it concerns, or in an erratum where it works around an error.
- **Avoid repeating errata.** The page lists them. Describe one only where something else needs it explained, and then cite its ID. A known error with no erratum gets one.
- **Conclusions, not investigations.** Say what's true and name the check in a few words ("matches UHSLC's Wellington"). Statistics, phase angles and sample sizes go in the erratum's `evidence`, or in the pull request where the check found no error.
- **Where no independent check exists,** say so once, in the bullet the check belongs to, as [Rigor](../../CONTRIBUTING.md#rigor) asks.
- **Nothing dated,** in the README or the code comments it points to. No "in November 2026", "not yet sent" or "until". Round a count that changes ("about 70 gauges").
- **Each caveat once,** in the bullet it belongs to.
- **Describe the data as stored:** stations, levels, times, datum, flags, freshness and known limits. How the adapter requests and parses, what it refuses or caches, and why the code chose what it did go under `## Running ingest` or in code comments.
- **Links to other sources** belong on each gauge's page, not in the README. A copy whose values differ is an erratum, and a link made or refused by decision is explained beside its entry in [`src/same-as.ts`](../../src/same-as.ts) or the adapter.
- **Leave out what changes nothing a reader does,** such as a mailbox for data the store doesn't hold.
- **Flags** maps the source's codes to the scale and says nothing the table says.
- **`## Running ingest`** is the last section, which the site leaves out. It holds how to run the source today: request limits, a backfill from nothing, and the scheduled runs. Commands for a one-time change belong to its pull request or migration. A command is changed only by someone who has run the new one.

Bullets are labeled with one or two words (`- **Datum:**`). A `## Known limits` section, where needed, comes after them, then `## Running ingest`. [`test/readme.test.ts`](../../test/readme.test.ts) checks the layout.

## Source errata

When a source publishes something wrong, such as values on the wrong clock or day, a gauge placed far from where it is, metadata that contradicts the data, or two endpoints that disagree, record it as an erratum, whether the adapter works around it or not. Each source's errata are in `src/sources/<source>/errata.ts`, reviewed with the code that handles them; nothing else holds them.

1. Add an entry to the source's `errata.ts` (start the file as `export default { errata: [], retired: [] } satisfies ErrataFile;`, with `ErrataFile` imported from [`src/errata.ts`](../../src/errata.ts), and import it in `errataFiles` in [`src/sources/index.ts`](../../src/sources/index.ts), which the tests check): an `id` (`<source>-<what>`, never reused), the `stations` it affects (store IDs, or `"every station"`), the UTC days of values it's in (`since`, and `until`, the day after the last; leave one out for an open end, both for an error in metadata), what's wrong (`error`), what the store does about it (`handling`: `corrected`, `flagged`, `dropped`, `refused`, `avoided` or `kept`, and `response`, in a sentence or two), how it was found (`evidence`), and a `check`, which reads the store back (see below). A `flagged` entry with stations and a span needs no code: the adapter registry flags that span `suspect` in the levels the store fetches or requalifies (extremes aren't flagged), keeping the source's own flag as `source_flag`. Run `requalify` over the span after it merges to flag the values already in the store, and again after an entry stops being `flagged`, to clear them, once any epoch or offset that replaces the flag is in the store (after the station refresh that applies it).
2. Cite the ID as ``erratum `<id>` `` where the adapter works around the error otherwise. The type check fails on an entry with no `check`, and the tests on a file that doesn't parse, an ID used twice or retired, and a citation no entry holds.

`publish` puts each station's errata in the `errata` column of `stations.parquet` and writes them to `errata.json`, with a link to the file each is in, and fails the run, after publishing, on an erratum that names a station the store doesn't hold.

Reports go to each agency in its own language, one message covering its errata not yet reported, to the channel in the adapter's `metadata.contact`, and only once a person has approved the text. `npm run errata` drafts that message for each source with entries that have no `reported` date (`npm run errata -- <source>` for some). An entry with a `report` but no `reported` date is held back, and the note says why. Once it's sent, set each entry's `reported` to the day and its `report` to where it went, naming the channel (the agency's contact form or published address), never a person; add the agency's answer to `report` when it comes. When the agency fixes the data, remove the workaround, refetch what it touched, and delete the entry, moving its ID to `retired`.

Each entry's `check` reads the store back, as a migration's check does, and throws where the store doesn't hold what the entry says: the error as the store keeps it, and what the store did about it, such as a span flagged `suspect`, values shifted, dropped or kept. It reads only the store, through the reader `npm run errata:check` gives it, never the source: bringing in data a source has changed is ingest's job, whatever the reason, and a check that fails after a refetch is how a change reaches the erratum. It gets its own entry, so it reads the entry's `stations`, `since` and `until` rather than repeating them, and reads a few station-days or station-years that show the error, throwing on an empty read rather than passing. `flaggedSpan` in [`src/errata.ts`](../../src/errata.ts) checks a `flagged` entry's span and `impossibleDropped` a level outside the store's span; a check adds what shows the error itself, such as an offset or a lag against another record the store holds. `npm run errata:check` runs every check against `STILLWELL_STORE` (`npm run errata:check -- <source or ID>` for some; `STILLWELL_STORE=https://stillwell.openwaters.io` reads the public store) and exits 1 on any failure. The Errata check workflow runs every check after each full Monthly or Refetch run on `main` that refreshed or refetched a source, and keeps one issue labeled `errata-check` open for each erratum whose check fails ([`scripts/errata-issues.ts`](../../scripts/errata-issues.ts)). It rewrites its own part of the issue when the check fails another way, leaving what a maintainer added, and closes the issue when the check passes or the erratum is gone. A failing check leaves the run green. A check that can't read the store leaves its issue as it is and fails the run, as do problems in an errata file. The sources in [`src/sources/server.json`](../../src/sources/server.json) refresh and refetch on the server's own schedule, so their checks read what the server had written when the run started. Dispatch it with sources or erratum IDs to check only those, such as after a backfill. When one fails, find out what changed: a source that fixed its data means the workaround comes out and the entry retires as above.

Anyone can report an error with the **Source error** issue form. A maintainer who agrees adds the entry and closes the issue.

## Withheld stations

A station whose owner refused permission to republish its data is withheld: never listed, fetched or published, and deleted from the store. A source names them with `withheld` (`Source` in [`src/schema.ts`](../../src/schema.ts)). The rule covers UHSLC's records and GESLA's copies of them: UHSLC withholds every series of a station number one of whose documentation files carries a notice marked `refused` in [`src/sources/uhslc/notices.ts`](../../src/sources/uhslc/notices.ts), versions the scan hasn't read included, and GESLA every copy of such a series and every record carrying such a notice. `ALSO_WITHHELD`, beside the notices, adds station numbers by hand, with the reason, where another source credits the gauge to a refusing contributor. Today that's the South African Navy Hydrographic Office's ([#80](https://github.com/openwatersio/stillwell/issues/80), [#82](https://github.com/openwatersio/stillwell/issues/82)): 27 stations, GESLA's 25 records of its gauges, UHSLC's Walvis Bay, `uhslc/220`, and UHSLC's Lüderitz, `uhslc/702`. Lüderitz's UHSLC documentation names no contributor, but GESLA names SANHO as originator and SANHO refused "any of our national tide gauge data", so `ALSO_WITHHELD` names 702. A refusal from any other contributor, such as one of GESLA's own, needs a rule of its own.

GESLA also withholds a record's ID from before IDs had to be URL-safe, once it lists the record under a URL-safe one. Such a move starts the new ID empty: run `ingest withhold gesla` to delete the old ID's files, then refresh the list, backfill the new ID and publish.

An adapter refuses to fetch a withheld station, and `backfill`, `compact` and `requalify` read the source's list without them, so a list not yet refreshed fetches nothing of theirs. Each refresh drops them from the list it read, from the snapshot it writes of that list, and from the source's bounds, daily files, empty-years record, backfilled years, requalify list and analysis, with its history, reporting them as removed rather than retired, and leaves them out of the sharp-shrink guard. It refuses to remove more than 5 stations or 2% of the list, whichever is larger, as likelier a wrong rule; `--accept-withheld`, the Monthly workflow's `accept_withheld`, lets that through once a person has checked the rule. While any withheld station the store has known, by the list, its history, the bounds, the daily files or the analysis, still has series files, every refresh's report says to run `withhold`, and the run fails, after writing the list; in the Monthly workflow, the publish job still runs after a failed list job, so `stations.parquet` drops the station either way. `publish` leaves out any the list still has, and doesn't count an erratum naming a withheld station as naming an unknown one. `withhold` deletes their files:

```bash
node scripts/ingest.ts withhold gesla
```

It finds every withheld station the store has known, from the source's list, its history, its bounds, its daily files and the directories of its files, and refuses more than the refresh's limit of those stations unless `--accept-withheld`. Then it deletes each one's directory under `obs/`, `extremes/`, `predictions/` and `predicted-extremes/`, later epochs included, and drops its rows as a refresh does. A local store's are deleted from disk; on R2 the AWS CLI deletes them with the store's `S3_*` credentials, since DuckDB can't delete objects, and refuses any other remote store, such as the public one over HTTPS. Each prefix ends in the station's encoded ID and a slash, so it names that station's directory alone, and an empty ID, `.` or `..` is refused.

To withhold stations in the R2 store once the change is on `main`:

1. Check in Actions that no Ingest, Compact daily or Monthly run for those sources, started from `main` before the merge, is still queued or running. Such a run uses the old code, which lists and fetches the withheld stations and could write their files back after `withhold` deletes them.
2. Dispatch Ingest with `withhold <source>` for each source the rule covers, such as `withhold gesla`, then `withhold uhslc`. Each runs in the source's group, so check that it started rather than show as cancelled.
3. Dispatch Monthly with `sources` set to those sources, `gesla uhslc`, which drops them from the lists and publishes `stations.parquet`. A run with `sources` set skips the `matches` and `links` jobs, so then dispatch Ingest with `matches --concurrency 16` and a timeout of 300 minutes, and with `links --concurrency 8`, as Monthly runs them, which drop the withheld stations' rows from `stations/matches.parquet` and `stations/links.parquet`.
4. Run `npm run ticon:inventory` against the refreshed public store and commit the [TICON inventory](../ticon-inventory.md) and its CSV, so GESLA's copies of withheld records are no longer named.
5. Take withheld stations out of the errata that list them, such as Mossel Bay's FD record in `gesla-uhslc-positions`. `publish` doesn't fail on them meanwhile.

The other order works for steps 2 and 3, since `withhold` finds stations the list no longer has, but this one deletes the values first. Rolling back the release that withholds them would list them again at the next refresh and fetch them again at the next backfill, so a rollback needs these steps repeated once the rule is back. Snapshots in `history/stations/` written before the refresh still list the withheld stations, without any values; neither command rewrites them.

A GESLA record whose values are another gauge's (`isDropped` in [the dropped-records list](../../src/sources/gesla/dropped.ts)) stays in the list, inactive with no products, but its stored files aren't deleted by a refresh or by `withhold`. `drop` deletes them, for the records whose files the source's rule names (`deletesFiles`), and only those with files; `--dry-run` lists them and deletes nothing. It runs from the Ingest workflow in the source's group. It drops their rows from the years file and the analysis as well, and the backfilled years of every record the rule names, with files or not, which `--dry-run` counts by station; afterwards `compact <source> --rebuild-bounds` and `publish` drop them from the bounds and from `stations.parquet`'s `first` and `last`, and Ingest `matches --concurrency 16` (timeout 300) and `links --concurrency 8` drop their rows from `stations/matches.parquet` and `stations/links.parquet`. Rolling back past the change that drops them lists them as active again, and a `backfill … all` on that build fetches them back:

```bash
node scripts/ingest.ts drop gesla --dry-run
```
