# Running ingest

[`scripts/ingest.ts`](../../scripts/ingest.ts) has fourteen commands: `stations`, `publish`, `links`, `matches`, `backfill`, `compact`, `requalify`, `analyze`, `fit`, `withhold`, `drop`, `misplaced`, `delete-years` and `years`. `stations` refreshes each source's list in the store, `stations/<source>.parquet`, for every source or the ones named, then writes `stations.parquet`, `stations/offsets.parquet`, `sources.json`, `errata.json` and their definitions (`datapackage.json` and the JSON Schemas, see [Published files](checks.md#published-files)), unless `--no-publish`; `publish` writes only those, from the lists in the store. Neither changes a file in the repo. `links` measures the offset between each pair of linked series that share no reference datum, from the stations as publish builds them and their levels, into `stations/links.parquet`, which the next publish carries MSL, LAT and chart datum through ([links reference](https://openwatersio.github.io/stillwell/docs/reference/links/)); the Monthly workflow runs it before publishing. `matches` compares every pair of stations within 10 km that a match could link, and every linked pair, by their hourly levels, into `stations/matches.parquet`, which the next publish links pairs that agree within 1 cm by ([Stations](../stations.md)); it prints the pairs that agree but aren't linked yet, linked pairs whose levels differ by 3 cm or more, and pairs that agree only with one clock moved by whole hours, and the Monthly workflow runs it before `links`, with the output in the job summary. A linked pair that differs is reported, never unlinked: check it and add an `UNLINKS` decision. Publish prints the same two lists. Before measuring, `links` and `matches` take out last month's rows naming a withheld station, which leaves its list, or a listed one that joins no group (`joinsNoGroup` in [`src/same-as.ts`](../../src/same-as.ts)), which neither compares again; a station listed without levels for another reason, or one no list holds, as when its list can't be read, keeps its rows. With `--prune`, either command only takes out those rows, measuring nothing, and writes its file only if it took a row out, reading the source lists rather than levels, and failing when a source `drop` covers has none; the Ingest workflow runs both that way after a `withhold` or `drop`, each in the group Monthly's job writes that file in, and a migration with a `withhold` or `drop` step runs both after it. A Monthly run limited to some sources skips both. Before writing a list it copies the previous one, less any withheld stations, to `history/stations/<source>/`, with a report of the stations added, retired, removed and changed, which it also prints and adds to a GitHub job summary. It keeps the previous list when the fetch fails, comes back empty or shrinks by half, when a station's terms differ from its source's, when the store has history for the source but no list, or when more stations changed datum at once than an adapter bug would explain (rerun with `--accept-epochs`, the Monthly workflow's `accept_epochs`, after checking them). A station the source stops listing stays, marked inactive; a withheld one leaves (see [Withheld stations](sources.md#withheld-stations)). A new source's first refresh starts its list; a source with series in the store but no list or history is refused rather than started over. A station's datum epochs, and the decisions about them in the source's `overrides`, are described in [Stations](../stations.md#datum-epochs).

```bash
node scripts/ingest.ts stations
```

Backfill stations' observations, extremes and predictions by year, with the end year exclusive. Pass a comma-separated list of station IDs, or `all` for every active station of the source (`--with-inactive` adds the inactive ones, for a history backfill):

```bash
node scripts/ingest.ts backfill rws hoekvanholland 2016 2025
```

```bash
node scripts/ingest.ts backfill bsh 506P 2026 2028
```

```bash
node scripts/ingest.ts backfill pegelonline 5990020 2000 2027
```

```bash
node scripts/ingest.ts backfill uhslc 001,329 1960 2026
```

Backfill skips a year whose file is already complete: a past year, asked for whole, whose file has values in every month, runs into the year's last week and holds no preliminary values (`yearDone` in [`src/backfill.ts`](../../src/backfill.ts)). So a run cut short, such as by the Ingest workflow's 6-hour cap, doesn't fetch those years again, and `--refetch` fetches every year anyway. A station's first and last years, and years with a missing month, are never complete, so they're fetched every run too. That rule still fetches every year with preliminary values on each run, so a campaign of many runs, such as the USGS record, passes `--skip-written` to skip every whole, ended year that has a file at all, from a listing of each station's files, and ends at the current year so it never fetches a year still under way. Compaction writes the current year's file for every live station each night, so from 2026 on (`COMPACTED_SINCE`) a year's file counts as written only if it has values in every month or holds values backfill wrote, which takes a read of those years. Compaction began in November 2026, so that year's files need a backfill before `--skip-written` trusts them. Otherwise it skips a file whatever it holds, so a year an earlier run wrote only part of, such as `backfill bsh 506P 2026 2028` above, needs `--refetch` or a run without `--skip-written` to fill in. A year a source returns nothing for writes no file. With `--skip-written`, a source whose metadata sets `empty_means_none` (its adapter throws on an outage rather than answer with nothing), or `skip_empty` (it can't show that, so publish still counts such a year inside a station's record missing), has backfill record a year with no file in `stations/empty/<source>.json` and skip it for 30 days, so a campaign's later runs don't ask again; after that, or without `--skip-written`, it's fetched again, in case the empty answer was an outage. Within a series' dates that still costs a request per year or month, unless the adapter asks only within each series' dates, as most do; its `observations` shows how it bounds a request.

A level outside −500 to 9,000 m (`SPAN_M` in [`src/span.ts`](../../src/span.ts)) is left out wherever it's fetched, and every writer counts what it left out and why: the log's line for each year says how many and which values (a fill value such as −9,999 shows by name), the run's summary on its page totals them, and a polled station whose fetch left out levels says so beside its name under the summary's stale stations. A year in which every level the source sent is outside the span isn't an empty year: with no level in its file, backfill writes its rows flagged `bad`, so the year has a file and counts as written, and the run lists the series years it wrote that way. A year whose file holds levels keeps them, as it does when a fetch comes back empty, and the run says what the source sent.

Every backfill also keeps, in `stations/backfilled/<source>.json`, each station's ranges of the whole years of its run that each datum epoch's span reaches into, by epoch, whose levels came back, values or empty, leaving out a year whose fetch failed and recording nothing for a station a stop cut short; the current year counts for a live station when the run reaches the present, and a `preliminary` refetch counts from the first January 1 it reaches. An empty answer includes the years an adapter answers without asking, outside the dates the source lists for the station. Compaction adds a year when it folds a station's values from the year's first hour, or its first step where that's longer, since it then carries the year from its start. Each write merges into the record as it is then. A `--skip-written` run over a campaign the store already holds records it cheaply, since the years it skips count, except one from 2026 on without every month and values backfill wrote, which isn't known to hold the whole year. A station that began partway through 2026 so stays missing until a run without `--skip-written` fetches that year. Publish turns that and the years file into each station's `missing_years` in `stations.parquet` and its source's `backfill` in `sources.json` ([`src/backfilled.ts`](../../src/backfilled.ts)), from the source's first year, the earliest file of its listed stations, to this year for a live station (last year on January 1, before compaction folds the new one), or for any other to the year after its last stored one or the last year a range covers, but not this year, which only a refetch brings. A year counts as had when no epoch's span reaches it, so no backfill can ask; when it has a file in its epoch's span, at a source that isn't polled hourly or before 2026 (`COMPACTED_SINCE`), or at an hourly one from then on with a range too, since compaction may have written it; or when a range covers it with no file and the empty answer is sure: the source sets `empty_means_none`, or the year is before the station's first stored year or, for an inactive station, after its last. An empty year inside the record may be an outage, so it stays missing, as does every year of a station with nothing stored, unless the source sets `empty_means_none`. An outage that answers empty for every year before a station's first values, or after an inactive station's last, isn't caught, nor are years outside wrong dates a source lists for a station. A station a stopped run left marked in the years file gets none, and withholding a station, or `drop`ping a record, drops its ranges.

`preliminary` in place of the station IDs takes every station, active or not, whose bounds hold a preliminary value, and fetches it from that value's month, or from the start date when that's later, to the end date or the end of the year of its last value, whichever is sooner. The start date is the cutoff: a station whose recorded value is before it is listed, in the output and on the run's page, and fetched only from the cutoff on, if it has values after it. Compaction and backfill look for preliminary values only from three years before this one, the Monthly cutoff, so a station is listed when its value falls behind the cutoff at the turn of a year, or after a killed backfill left it lowered to where its fetch began. Its next read then moves the value to the earliest from the cutoff on, or clears it; a station whose files end before the cutoff has its value cleared there and then. So older values still preliminary are listed once and then left. A `preliminary` run with an earlier start than the cutoff reads from that start, so it sees what it fetched. `--skip-unscreened` leaves out a station with at least a year of record in its current epoch and no value its source screened, kept in the bounds as `screened`, which compaction and backfill set from the files they read (backfill from the cutoff year on). A value counts as screened when its `source_flag` isn't preliminary, or, in a file from before `source_flag`, when its flag is good or interpolated, since a suspect or bad one there may be QC's alone. A source whose stations may never be screened passes it in its refetch `schedule` but in January, so once a year every station is read again and one whose office began screening rejoins. After fetching a station's levels, and for every station `preliminary` picks, backfill reads its earliest preliminary value in the current epoch again into the bounds, every 100 stations so a run stopped by its time limit keeps most of them, and one the source has finalized drops out. Other backfills first lower each 100 stations' values to where their fetches start, but no earlier than the cutoff year, behind which nothing looks, so a run killed partway leaves them too early, which the next refetch corrects, rather than too late:

```bash
node scripts/ingest.ts backfill coops preliminary 2023 2026-11-01
```

`--first <file>` runs the stations a file names before the rest: one ID per line, or a CSV with an `originator_id`, `id` or `station` column, such as a report's CSV. An Ingest run reads only files committed to the repository. An unsharded run stops if the file names none of the stations; a shard can hold none of them, so it doesn't.

```bash
node scripts/ingest.ts backfill usgs all 2007 2026 --skip-written --first stations.txt
```

`--shard 2/8` takes the second of eight sets of stations, split by a hash of their IDs so a station's shard never changes, for separate jobs. The Ingest workflow runs a source's jobs one at a time, in its `store-<source>` group with that source's compaction runs, so there dispatch each shard after the last one finishes. A shard holds that group for hours, so the source's compaction skips meanwhile if a shard spans 00:40 UTC. Compaction's 6 days catch up a gap shorter than that, so leave a gap between shards for it to run, or run `compact <source> --days 6` between them; after back-to-back shards over more than 6 days, run `compact <source>` with `--days` covering the gap, up to the 30 days the daily files are kept. That's how the current year gets backfilled: both modes fetch a year still under way in full on every run, so a run over it never resumes, and it has to be split into shards that each fit in one run, such as `backfill usgs all 2026 2027 --shard 1/4`, then `2/4`, `3/4` and `4/4`, each dispatched with `timeout` at 360 minutes, since one stopped partway starts over on its next run. Shards running at once need a matrix workflow, which doesn't exist yet. Every backfill also rewrites the source's whole bounds file, `stations/bounds/<source>.parquet`, after each 100 stations, so two shards writing at once lose each other's preliminary values. Such a workflow has to run them one after another in the source's group, or keep shards from writing the bounds.

Fold the last whole UTC days of the daily files (`--days`, 1 by default, which is yesterday, and at most 30) into each station's year files under `obs/`, each row into its datum epoch's files, carrying `received`. Each year file is read, merged and written whole, so a failed run leaves the file it had, and a file the fold doesn't change isn't written. The daily files' level and flag win over the file's, except that a value the source hasn't finalized never replaces one it has, such as a verified backfill. Both are judged by the source's own flag, kept as `source_flag`, so QC marking a verified value suspect doesn't unfinalize it:

```bash
node scripts/ingest.ts compact pegelonline --days 6
```

Then it writes each station's first and last level, over all its epochs, to `stations/bounds/<source>.parquet`, which `stations.parquet` is built from. Compact daily rebuilds it with `publish` once every source's compaction is done. It lists the source's files under `obs/` and reads only the end years it can't take from the fold or the bounds it has; `--rebuild-bounds` reads every station's end years again, as the first run does. Beside them it keeps each station's earliest value in its current epoch that the source sent as preliminary, which `backfill … preliminary` starts from: the one it knows, unless a file it folded holds an earlier one. A station new to the bounds, or every station with `--rebuild-bounds`, has its files read from three years before this one (`REFETCH_YEARS`, the refetch's cutoff) until one holds a preliminary value, at most four files. Bounds an older build wrote have no `preliminary` column, and compaction keeps them that way, since filling it in reads up to four files for every station, more than Compact daily's 50 minutes may hold at USGS. Run `compact <source> --rebuild-bounds` from the Ingest workflow, with a longer `timeout`, to fill it in; until then `backfill … preliminary` refuses to run, and other backfills leave the bounds alone.

Both print a summary (stations updated, stale, failed and waiting on a held datum change, and values written), and add it to the workflow run's page in Actions.

Work the flags of stations' observed levels out again from what the store holds, over the years given (end exclusive), without asking the source, so a change to QC's rules, or to a station's analysis, reaches values already stored. Pass station IDs or `all`, which takes inactive stations too:

```bash
node scripts/ingest.ts requalify smhi all 1880 2027
```

A stored level outside −500 to 9,000 m (`SPAN_M` in [`src/span.ts`](../../src/span.ts)) is dropped, as a fetch drops one, and the summary counts them and says why, so requalify over the years that hold them removes them from the store. A year that holds nothing else keeps its file, with a warning, since a year file always has some rows; `delete-years` deletes such a file. Each year file starts over from its `source_flag` and the errata spans the source's adapter flags (its `suspect`: the spans of the source's `errata.ts` and of errata listing the station as a copy, such as REFMAR's Pointe-à-Pitre clock, and spans the adapter finds itself, such as GESLA's datum jumps, which it finds in the store's copy of the record and can't when that ends more than a year inside the record's stated ends, as where GESLA's own file holds nulls there; the record then keeps the flags it has, among them the datum jumps backfill found in GESLA's whole file, gets its `errata.ts` spans and the current QC, which can only make a flag worse, so a looser rule or a retired erratum never clears a mark there, and the run lists it under warnings and counts it requalified), then QC runs with the current rules, with the years either side read too, so a flatline or spike across New Year is judged whole. A file is written only when a row changed. A value from before `source_flag` was kept gets it from its flag where that's better than suspect, since QC only marks values suspect or bad; a suspect or bad one may be QC's, so its flag stays until a backfill fetches it again. Backfill QCs the whole year it writes the same way, with the years either side as they are when it runs, though the values it didn't fetch keep their flags; a year written before the one after it existed isn't judged against it again until `requalify` runs. The poller starts a station's live values over from `source_flag` each time a fetch brings values, except within the longest flatline rule's length of its oldest value, and judges them over its last 7 days; compaction folds those flags into the current year's file as they are, so `requalify` there gives flags judged over the whole year. Its summary counts as values the rows whose flag changed, so a first run that only fills in `source_flag` writes files with no values. A station with a file holding more than one datum, or whose source's spans fail for any other reason, fails before any of its files is written. Stations run in worker threads, one per core at most, `--concurrency` stations shared among them, each worker's DuckDB capped at 1 GB and two threads and its JavaScript heap at an equal share of the rest of the machine's memory (at least 1 GB); a worker that runs out leaves its stations marked in the years file for the next reconcile, though with the current DuckDB its end aborts the whole run, as running out of memory on one thread did. Each year is judged with only the part of the years either side that QC's rules can see from it (`nearContext` in [`src/qc.ts`](../../src/qc.ts)), which gives the same flags as the whole years. `--shard 2/8` splits `all` as backfill does. The Monthly workflow's full refresh, on the 2nd, requalifies the years holding the last two months for every source, after analysis, in the source's list job, with `--budget`, which starts stations only for that many minutes: 90, or less once the job has run over three and a half hours. With a budget, `all` takes only the stations the years file has a file in range for, or has marked, and every one saved by an earlier run, or every station for a source without a years file, and saves the ones it didn't start in `stations/requalify/<source>.json`, each with its years, and those that failed with the run's years, or their saved years and the run's where their batch couldn't be marked; the next budgeted run starts with them, each over its saved years and the run's together, so a source too big for its budget doesn't leave the same stations out each time. The run's summary says how many it didn't start, first among its warnings. `--budget 0` starts none and saves them all, which the Monthly step does when its job has no time left. Compaction folds the last days of a month again for a few nights after, with the daily files' flags, so each month gets the current rules judged over the whole year at the next month's run. Run it from the Ingest workflow, which runs it in the source's group, as it does backfill.

Measure what the store can tell about each station from its levels, and keep it in `stations/analysis/<source>.parquet`: today, whether its levels carry a tide, which picks QC's flatline, outlier and residual-jump rules for it ([the rule](../stations.md#analysis)). It judges the stations that are due, those with no verdict, a verdict over a year old, one whose list no longer gives the offset or ground its verdict read (`sea_level`), or one under other rules (`RULES` in [`src/store/analysis.ts`](../../src/store/analysis.ts), or `JUDGE`; a change to a QC rule or to `qcFor` adds a version to `RULES_HISTORY` naming the one rule it's confined to, or null where it can reach any station, and requalifies only the stations whose QC options use a rule changed since their verdict, and a change to the verdict's rules bumps `JUDGE`, which requalifies only the stations whose QC changes), or every station with `--all`, and prints those whose QC changes, writing every 500 stations; `--requalify` then requalifies those, and every station after its first verdict, over every year, 100 at a time, marking the stations it finished done as others finish, at most every 5 minutes, and after each batch, and starts stations only for `--budget` minutes (120 by default) so the source's compaction isn't held off for long; the stations it starts run to the end, which for a source of 1-minute series such as PEGELONLINE's coastal gauges takes a couple of minutes of one CPU each, so a run goes over its budget by about that times `--concurrency` over the machine's cores. What it doesn't reach, or a run stopped partway leaves, waits for the next. The Monthly workflow runs it for every source it refreshes, before publishing. Run it from the Ingest workflow, which runs it in the source's group:

```bash
node scripts/ingest.ts analyze usgs --requalify --concurrency 8
```

Fit harmonic constants to a source's stations from their levels in the store, into `fits/<source>.parquet` and `constituents/<source>.parquet` ([`src/fit/`](../../src/fit/), with each column defined in [`src/store/files.ts`](../../src/store/files.ts)). [Harmonic fits](../fits.md) has the method and the reasons for each choice. A fit reads final values stamped on a UTC hour, every datum epoch in the current datum, over up to 19 years before a held-out year it is then scored on: the latest year of final values in which half the station's hours can be scored. Final values are the source's verified ones, with preliminary ones from before the station's `source_qc_start`; for a source that never finalizes, they are the measured values of years that ended at least its `settles_after_months` ago, and a source with no such figure gets a row per station saying so. It reads whatever the store's flags allow: an erratum's `flagged` values are suspect and stay out, and its `kept` values are read, with the erratum recorded in the fit's `inputs` ([Source errata](sources.md#source-errata)).

It needs the source's years file. A station is fitted again when anything its fit depends on changes: a year file's version, a year becoming final, an epoch or its conversion, `source_qc_start`, an erratum that names it or its handling, the candidate list or its order, the source's rule for final values, the fitting engine's version, or the method's (`METHOD` in [`src/fit/series.ts`](../../src/fit/series.ts)); `--all` fits every station again. A station whose year files are being written is left as it was for the next run, and a source that finalizes isn't fitted at all while any of its stations is, since its final year can't be told. Station IDs, separated by commas, or `--shard` limit a run, and both files are written after every 25 stations. Each candidate row carries its fit's `version`, since a run that stops between the two files leaves them a batch apart until the next run. A fit is computation on one core, about two minutes and 600 MB for a station's 19 years, so each station is fitted on a worker thread of its own, `--concurrency` of them at once and no more than the machine has cores ([`src/fit/workers.ts`](../../src/fit/workers.ts)). Measured on four SMHI gauges, four at once took 103 seconds and peaked at 1.4 GB, against about 270 seconds one after another. The Ingest workflow's job has 180 minutes unless given more, up to 360. A source with more takes more than one run: each fits the stations still due and keeps what the last one wrote, losing at most the 25 since its last write. Every station of a source comes due together when its final year moves on, or the engine's or the method's version changes. Shards of one source run in the same `store-<source>` group, one after another, and a run holds that group while it works, so the source's backfills, compaction and refresh wait for it. It runs from the Ingest workflow and not as a migration step, which has to finish in one job.

`withhold` and `drop` take a station's rows out of both files with its values.

```bash
node scripts/ingest.ts fit smhi 2130
```

An epoch opened with a start in the past, by a reference the source names or a split in `overrides.splits`, leaves rows from that start on in the earlier epoch's files, outside its span, which no reader or writer takes. Once a backfill has written them into the epoch that holds their time, `misplaced` drops each such row whose time that epoch's file has, in every product, and deletes a file left empty. It keeps a row that epoch lacks, or that no epoch's span holds, and lists each file with how many it kept and the first one's time. `--dry-run` lists what it would do. Then rebuild the bounds with `compact <source> --rebuild-bounds` and publish:

```bash
node scripts/ingest.ts misplaced rws --dry-run
```

A year file of levels can't be emptied, so requalify and compaction keep one whose levels all fall outside the span, and the store has no other way to take it out. `delete-years <source> <station> <epoch> <year,...>` deletes the named year files of one station's epoch, refusing before it deletes any if a file holds a level inside the span or a value not flagged `bad`, and drops their rows from the source's years file. A named year with no file is skipped, so a run that stopped partway can run again. It takes no `--dry-run`. It leaves the bounds and `missing_years` as they were: rebuild the bounds with `compact <source> --rebuild-bounds` and publish, which lists a deleted year as missing unless the source's empty answer is sure there (`missingYears` in [`src/backfilled.ts`](../../src/backfilled.ts)). A station takes one command, so a migration lists a step for each station. The station stays in its list, so the command needs no prune steps. Run it from the Ingest workflow, which runs it in the source's group:

```bash
node scripts/ingest.ts delete-years usace MVS.Bethany-Marrowbone_Cr 1 2025,2026
```

Every run that writes or deletes a year file of levels, `backfill`, `compact`, `requalify` and `delete-years`, keeps `stations/years/<source>.parquet` in step: each year file with its hours, values by flag and a version, for readers to tell a year with no values from a file they failed to read ([which years a station has](https://openwatersio.github.io/stillwell/docs/reference/observations/#which-years-exist)). They mark each batch of stations before writing and set their files' rows after, and compaction then lists the source's files and reads any a stopped run left without a current row ([store layout](../stations.md#store-layout)). A source with files but no years file gets one only from `years`, which reads every year file of levels the source has, and resumes where a run stopped by its time limit left off. `--rebuild-years` reads every file again even when the years file has them, or can't be read; if it's stopped, run `years` again without the flag to finish. Run it from the Ingest workflow, which runs it in the source's group:

```bash
node scripts/ingest.ts years usgs
```

Compaction checks only that every year file has a row and every row a file, not that a row's version still matches its file. Anything that writes year files without keeping the years file leaves rows whose version no longer matches the file, and compaction rereads such a station only if a stopped run left it marked: a rollback to a build from before the years file, a run from an older local checkout, or a restore of `obs/` from a backup. Afterwards, once the current build is back, run `years <source> --rebuild-years` for each source whose files it wrote.

These environment variables choose where it writes:

| Variable                                                  | Means                                                                                                                                                            |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `STILLWELL_STORE`                                         | The store: a directory, `data` by default, or an `s3://` URL.                                                                                                    |
| `STILLWELL_RESTRICTED_STORE`                              | A separate, private store for sources whose terms bar republishing their data. Ingest refuses to write one without it, and refuses one that is the public store. |
| `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Credentials for an `s3://` store such as R2, the same variables crowd-depth reads. `S3_REGION` defaults to `auto`.                                               |
| `STILLWELL_CACHE`                                         | The response cache, `.cache` by default.                                                                                                                         |

If a source starts reporting a station in another datum, `ingest stations` opens a datum epoch for it and reports it. A change it holds for a decision (soon after the last one, or back to an earlier reference) fails the run on every refresh until the source's `overrides` decide, and `backfill` and the poller skip that station meanwhile. `backfill … all` skips inactive stations.
