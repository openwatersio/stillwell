# Japan Oceanographic Data Center (`jodc`)

Hourly tide levels at 126 Japanese tide gauges that the Japan Coast Guard (31, Syowa Station in Antarctica included), the Geospatial Information Authority of Japan (25) and port authorities (70) run, back to 1910 at the oldest, from JODC's [tide data service](https://www.jodc.go.jp/vpage/tide.html) in J-DOSS. JODC also serves 81 of the Japan Meteorological Agency's gauges, which the `jma` source reads from JMA itself, so they aren't listed here.

- **License:** JODC serves every record to anyone. The download page asks for a purpose, country and type of institution before each download, but it collects no name or address and the files themselves are open URLs. Its [J-DOSS terms](https://www.jodc.go.jp/jodcweb/JDOSS/index.html) ask that work using the data credit JODC and send it a copy, and say 「無断で、データ等を複製して第三者に提供しないようにしてください」 ("don't copy the data and provide it to third parties without permission"); the tide pages add "No reproduction or republication without written permission". The Japan Coast Guard's general [terms](https://www1.kaiho.mlit.go.jp/copyright.html), which the same pages link to, follow the government standard terms (compatible with CC BY 4.0) but exclude content under rules of its own, which these are. Permission to republish was asked for on 8 November 2026 ([#47](https://github.com/openwatersio/stillwell/issues/47)). The store carries it meanwhile, on the expectation that permission is given, with `commercial_use` false on every station until JODC answers. If JODC refuses, a `withheld` rule added to the adapter takes its stations out, and `ingest withhold jodc --accept-withheld` deletes their files, as for SANHO's; GESLA's copies of JODC's records would need a rule of their own. Each station's attribution names JODC and the observing agency.
- **Contact for errors:** jodc@jodc.go.jp, from JODC's [contact page](https://www.jodc.go.jp/jodcweb/contactUs.html).
- **Stations:** every station in JODC's list, [`station_info.json`](https://www.jodc.go.jp/vpage/tide/station_info.json), a GeoJSON file of codes, names in Japanese and in capitals, positions and first and last years, but the 81 whose codes start `MA`, which are JMA's. The agency comes from the code: `HD` for the Japan Coast Guard, `GS` for GSI, four digits for a port authority. IDs are `jodc/<code>`, the codes TICON's `jodc_*` records carry (`jodc/GS01` for `aburatsubo-gs01-jpn-jodc_giaj`). Every one of TICON's 126 records from JODC's three other agencies has a station here; the inventory reports those whose station is inactive as unmatched, as it does every source's. Twenty of the Coast Guard's records also declare an originator, `jhod/<number>`, the Hydrographic and Oceanographic Department's own station number, which isn't a JODC code (`jhod/0136` is Tokuyama, but `jodc/0136` is a port gauge in Tomakomai), so TICON's records are matched by the code in their ID. A station whose record reaches within two years of the newest of its agency's is active: JODC adds a year at a time, a year or more late and to each agency on its own, so the list ends at 2023 for GSI and the ports and at 2025 for the Coast Guard. That's 110 today; the other 16 ended between 1973 and 2022, Syowa Station in 2022. Names are JODC's English ones in title case. GESLA's copies of these records link to them by code. They're never linked to JMA's stations (`SEPARATE` in `src/same-as.ts`): where both measure at one port, as at Maizuru or Hachinohe, they're different gauges on different datums. Two different places can share a name: GSI's Kure (`GS13`, 久礼, in Kōchi) is 110 km from the Coast Guard's Kure (`HD13`, 呉, in Hiroshima).
- **Files:** one zip per station, `vpage/tide/<code>.zip`, with its whole record as a text file per year, `<code>_<yyyy>.txt`, 30 to 300 KB in all. Each line is a local day: the code, the date as `yyyy/mm/dd`, then 24 levels for hours 0 to 23, comma-separated ([format](https://www.jodc.go.jp/jodcweb/JDOSS/formatTide_j.html)). A backfill asks for a year at a time, so the last 4 stations' records are kept in memory, one for each of backfill's workers, so each zip is usually read once a run (a worker slow to write can find its record evicted and fetch it again), and a year outside a station's first and last years isn't asked for. A zip gains a year in place, so it's always fetched fresh rather than from the disk cache. A zip that fails, or holds a line the adapter can't read, fails all of that station's years in the run, rather than be asked for again for each one.
- **Levels:** centimeters above the station's zero of tide height, as meters, `9999` where missing. A few hours hold `999`, `9901`, `9990` or `9996`, as at several Coast Guard gauges in 2009, which QC flags suspect or bad. A line dated day 00 is read as the day after the one before it (erratum `jodc-day-zero`), and a year a zip holds twice is read once (erratum `jodc-zip-duplicates`). JODC flags nothing and publishes final values only, so every value is `good`.
- **Times:** 「時刻は日本標準時（世界時 +9:00、但し昭和基地は世界時 +3:00)」: JST, UTC+9, but UTC+3 at Syowa Station (`HD50`), converted to UTC. A year's file starts at local midnight, 9 hours (3 at Syowa) before the UTC year, so a UTC year's last hours come from the next year's file. The adapter reads every year's file, so it keeps those hours, which TICON's JODC records lose: their epochs end at 15:00 UTC on 31 December, the year-end truncation slackwater-database found in GESLA 4.0. A UTC year before the record's first file would get only those hours, so they're dropped (a year missing within the record keeps them), and a station's `record_start` is the first UTC year's start.
- **Clock check:** against UHSLC's fast delivery, which UHSLC converts to UTC itself, the Coast Guard's gauge at Naze (`HD22`) fits at a lag of 0 in 2010 (r 0.993), and Syowa Station (`HD50`) at 0 (r 0.948) on UTC+3. Against TICON's JMA record at the same port, Maizuru's Coast Guard gauge (`HD24`) fits at 0 in 2005. Against their own TICON records, Kure (`GS13` and `HD13`), Oshoro (`GS04`), Aburatsubo (`GS01`) and Moji's port gauge (`9010`) fit at 0 in 2015. K1's lag is within 5 minutes everywhere, so there's no 12-hour error either. Years before 2005 aren't checked, among them Japan's summer time of 1948 to 1951, whose files may be an hour off in summer.
- **Datum:** each station's zero of tide height, `ZERO`, the name GESLA gives it. Each station's [attribute page](https://www.jodc.go.jp/TideAttrib/tide_attrib_8413_e.htm) gives it below the station's standard mark and T.P., but `datums` is empty: those pages are old HTML, one request each, and JODC doesn't say whether a zero moved during a record or whether earlier years were shifted to it.
- **Freshness:** JODC adds each agency's year in a batch: the Coast Guard's zips were last written in February 2026, GSI's and the ports' in June 2025. Nothing runs hourly, and since no value is preliminary, the Monthly refetch doesn't run either, so a new year comes in only from the yearly backfill below.
- **Limits:** JODC publishes no rate limit. Its robots.txt disallows `/cgi/` and others, not `/vpage/`. Requests start a second apart.
- **Not used:** JMA's gauges (`MA` codes), and JODC's other products, such as tidal constants.

## Backfill

Monthly refreshes JODC's list on the 2nd; dispatch Monthly with `sources: jodc` once the adapter is on `main`. Then backfill through the Ingest workflow. `all` takes active stations only, so the 16 inactive ones are named in a second run:

```bash
node scripts/ingest.ts backfill jodc all 1910 2027 --skip-written
```

```bash
node scripts/ingest.ts backfill jodc 0101,0138,3002,3003,8413,HD01,HD02,HD03,HD04,HD07,HD12,HD17,HD24,HD26,HD30,HD50 1910 2027 --skip-written
```

That's 126 zips, about 15 MB, at a second each, and about 4,700 station-years to write, so each run fits in one Ingest run. Once JODC has added a year, dispatch Monthly with `sources: jodc` first, since a backfill asks for nothing past each station's last year in the store's list, then run it again over the last three years with `--refetch`, which also picks up values JODC revised. The refresh's change report lists any station the new list retires, and `all` takes active stations only, so name those in a second run like the one above:

```bash
node scripts/ingest.ts backfill jodc all 2023 2027 --refetch
```
