# ISPRA (`ispra`)

10-minute sea levels from the Rete Mareografica Nazionale (RMN), Italy's national tide gauge network, run by ISPRA, the Istituto Superiore per la Protezione e la Ricerca Ambientale: 36 gauges, from 2010 to October 2023, from the monthly CSV files in ISPRA's [open data repository](https://rep.isprambiente.it/). The network's public site is [mareografico.it](https://www.mareografico.it/).

- **License:** [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), so every station goes to the public store and is tagged for commercial use. Two ISPRA pages state it: the legal notes on mareografico.it ("ISPRA releases them with the open CC-BY license, as they are", version 4.0 International, with a disclaimer that the values come from non-validated dynamic data and that ISPRA's own database prevails where it differs) and the footer of every page there. The network's RDF record names the same license and ISPRA as publisher. The CSV files carry no license statement of their own. Credit is "ISPRA", with the network's DOIs, [10.83182/ispra-rmn](https://doi.org/10.83182/ispra-rmn) and [10.83182/ispra-ron](https://doi.org/10.83182/ispra-ron). The terms say what the store changed: levels converted to meters and flagged preliminary.
- **Contact for errors:** [mareografico.it](https://www.mareografico.it/), the network's site, which publishes no address.
- **Stations:** every gauge the [RDF dump](https://rep.isprambiente.it/downloads/lod/rdf/rmn/kg/rmn_dump.nt.gz) lists with level files (it also lists air and water temperature, pressure, humidity, wind and radiation files, which the store doesn't read). The store's ID is the name the files go by, such as `ispra/napoli` for `napoli_hydrometric_<YYYYMM>.csv`. The name is the one in the series' English label ("Palinuro", where the platform's name is the municipality, "Centola"), and the position is the platform's. Every station is `coastal`, in Italy (`IT`), and 10-minute. All 36 are `active`, as the adapter reads no status from the dump, and none is `live`: see Live values. mareografico.it shows 40 gauges. Arbatax, Cetraro, Marzamemi, Milazzo and Pozzallo have no files in the repository, and the dump lists Isole Tremiti, which mareografico.it names Tremiti.
- **Files:** `https://rep.isprambiente.it/file/rmn/<station>_hydrometric_<YYYYMM>.csv`, a month each, CRLF line ends, a `UTC;Level` header and rows such as `2014-01-01 00:10:00;-25.7`: UTC, every 10 minutes, centimeters. A month's file can end early (Venezia's April 2022 ends on the 19th). The dump lists 5,138 level months, 2010 to October 2023, and many of them return 404 (erratum `ispra-listed-months-missing`): of Venezia's 166, 100 resolve, January 2014 to April 2022. The adapter asks only for listed months and skips a 404, so a station's coverage is what the repository serves. A file with a row it can't read (a blank or non-numeric level, a date that doesn't exist, an extra field) or two levels for one time fails the station, since ISPRA documents no missing-value marker. A time repeated with the same level is read once.
- **Flags:** every file is validation level L0, raw and unvalidated, and ISPRA publishes no validated version. Every value is `preliminary` and stays so, so `finalizes` is false and the monthly refetch skips the source. The store's QC still runs.
- **Datum:** `ZERO`, the gauge's own zero. The files give a level only, and neither the files, the dump nor the legal notes say how a gauge's zero relates to Italy's national datum (Genova 1942) or to mean sea level. Napoli's 2014 readings run from −38 to +38 cm. mareografico.it has a levelling section and a table of ellipsoidal heights that may give them, which the store doesn't read. A station's levels convert to no other datum until ISPRA's station sheets say how.
- **Live values:** none. mareografico.it shows the last 24 hours to 7 days of each gauge's 10-minute levels, in meters, and its footer gives the same CC BY 4.0 notice, but the figures come from a script-generated page whose address carries a key from the visitor's session, behind a script-run bot check, and no documented API sits behind it. The adapter doesn't use it, so `hourly` is false and new values arrive only if ISPRA adds months to the repository.
- **History before 2010:** mareografico.it's data archive lists "pre-NTN data" for 23 gauges, from stations that the local hydrographic services ran before the network, with sea level only, collection starting in different years and "the level reference is not unique". It also lists hourly levels, daily means with a Bloomfield filter, and tidal constants. These come through the site's session-driven forms, with no files or terms of their own, so the store doesn't read them.
- **Limits:** ISPRA publishes none. Requests start at least a second apart. A month is about 100 KB, a year of one gauge about 1.2 MB, and the dump 7 MB, read fresh on every run.
- **Times:** `UTC` is UTC. No clock check has been run.

## Backfill

The Monthly workflow refreshes the list on the 2nd; Compact daily needs the list in the store. The archive is closed, so one pass fetches it all. Through the Ingest workflow:

```bash
node scripts/ingest.ts backfill ispra all 2010 2024 --skip-written
```

That is one request for each of the 5,138 listed months, a second apart, whether or not the file exists: about an hour and a half, within one Ingest run.
