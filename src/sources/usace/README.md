# USACE CWMS (`usace`)

Stage from the US Army Corps of Engineers' Corps Water Management System, read through the public [CWMS Data API](https://cwms-data.usace.army.mil/cwms-data/) (CDA; [docs](https://cwms-data-api.readthedocs.io/), [source](https://github.com/USACE/cwms-data-api)). It covers the district offices on the Mississippi, Ohio, Missouri and their tributaries: MVS, MVK, MVM, MVN, LRL, LRP, LRH, LRN and LRC.

- **License:** U.S. Government work, public domain. CDA has no license or terms page, and its responses carry no license, but the stage is data the Corps produces, which [17 U.S.C. § 105](https://www.law.cornell.edu/uscode/text/17/105) keeps out of copyright, and [33 U.S.C. § 2342](https://www.law.cornell.edu/uscode/text/33/2342) requires the Corps to "make publicly available, including on the Internet, all data in the custody of the Corps of Engineers" on its water projects' operation and water management, "as quickly as practicable." CDA's code is under the [MIT license](https://github.com/USACE/cwms-data-api/blob/develop/LICENSE.md). The Corps asks for no attribution; "U.S. Army Corps of Engineers" is carried. CDA's web page shows the standard DoD consent banner ("provided for USG-authorized use only", with consent to monitoring), which every DoD site shows; it's a monitoring notice, not a license, and the API serves the data without a key to any origin (`Access-Control-Allow-Origin: *`). Older Corps district pages say the United States assumes no liability for the data's accuracy, which `terms` carries.
- **Request limits:** none published and none measured. CDA sends no rate-limit headers, and 40 one-year requests in a row on 2026-11-04 all answered 200, in 0.5 to 2 seconds each. Throttling (429) and server errors are retried with backoff, as for every source. Stay polite anyway: a backfill runs four stations at a time and each station's requests one after another.
- **Stations:** one per CWMS location with an observed `Stage.Inst` series, from each office's `catalog/TIMESERIES` and `catalog/LOCATIONS`, about 1,350 in all. Most are river gauges, but stage is any water surface the Corps measures, so the list also has reservoir pools, lock and dam headwaters and tailwaters, and the riverside and landside of pump stations. Only locations CWMS calls a stream are `kind: river` (about 410); the rest are null. Piezometers and observation wells (`…-Piezometer B1`, `…-OW7L`), which read groundwater in a dam's foundation, aren't listed. The ID is `<office>.<location>`, such as `usace/MVN.Baton_Rouge`, since location names are only unique within an office, with anything but letters, digits, `.`, `_` and `-` replaced by `_` (`MVK.Columbia L&D-Lower` is `usace/MVK.Columbia_L_D-Lower`), so an ID needs no escaping in a lake path, URL or shell argument; of two new locations that would share an ID, the first by name gets it. Some gauges appear in two offices' databases under different names (Baton Rouge is `MVN.Baton_Rouge` and `MVK.Baton_Rouge`); each is listed, unlinked, and positions are CWMS's own: MVN puts Baton Rouge at 29.43° N, about 110 km south of the gauge, where MVK has 30.45° N. A location placed outside the contiguous US isn't listed: some sit at 0,0 or at a placeholder such as 9.09, 9.09 (MVS's Anoka), and a few have the longitude's sign dropped (LRL's Buck Creek, MVK's Pine Bluff). An office that answers with no series or no locations fails the refresh, and the committed list stays.
- **Which series:** a location usually has several. CWMS names each `<location>.Stage.Inst.<interval>.<duration>.<version>`, and the version is each office's own label. Taken are regular series (5 minutes to a day, not versioned) whose version ends in `rev` or `raw` or is one of `OBS`, `OBS-USGS`, `Observed`, `MVM-PUB` and `historic-data-merge`. Left out are forecasts (`Fcst-NWS-…`, `CWMS-Forecast-…`, river forecast center `…Shef-CA` and the like), statistics (`AVG1935TO2024`, `Bankfull`) and versions that name a datum (`rev-NAVD88`, `NGVD-29`, `LWRP`), which are the stage converted to that datum. Of those, a location's series is the first by: still reporting (its catalog latest time within half a year, since the catalog's extents lag the data by weeks), finer than daily, revised (`rev`) over `raw`, finest interval, then longest record. So a daily series, such as an `MVDhist-rev` record back to 1861, is taken only where nothing finer is still reporting. The pick is kept as `series` in the source's list in the lake, and backfill reads that series. A refresh keeps a station's series while CWMS still lists it, even when another would now rank first, so a station's files never switch series. A committed station's ID belongs to the location its series is at: another location that now maps to the same ID is skipped, with a message, and if the station's own location is gone it goes unlisted, so an ID never moves to another gauge. When CWMS stops listing the committed series, the station keeps it but is marked inactive, and the refresh that marks it prints the series CWMS now offers and exits nonzero, so a person sees it in the commit. Left inactive, the station is retired; setting its `series` to the one CWMS now offers brings it back. A location that loses every observed series stops being listed, and goes inactive as any unlisted station does. `stations.parquet` doesn't carry `series`, so a station read from there (as the live Worker will) takes it from `source_url`, which names it.
- **Datum:** every level is stage, meters above the gauge's zero, named `GZ`. That stays fixed when an office changes which vertical datum it quotes. Where the location gives the gauge zero's `elevation` and names NGVD29 or NAVD88 as its `vertical-datum`, `datums` carries that elevation, so `level_m + datums.NGVD29` is the level above NGVD29. Spellings such as `ngvd29` and `NAVD88(2009.55)` count; `LOCAL`, `COE1912` and blanks don't. An elevation of exactly 0 is left out: offices give 0 both to gauges set at the datum and to locations they have no elevation for (MVK lists Baton Rouge at 0 NAVD88, MVN's description puts it 0.71 ft off). Checked against USGS: St. Louis 379.58 ft NAVD88 and Vicksburg 46.23 ft NGVD29 match USGS 07010000 and 07289000. About 590 stations get an NGVD29 offset, 400 a NAVD88 one, and 370 none. A refresh that sends no offset keeps the committed one, as for every source.
- **LWRP:** not in `datums` yet. The 2007 Low Water Reference Plane is a sloping plane, and CWMS has no structured LWRP offset for stage: 12 MVN gauges give it only in prose in the location `description` ("To adjust NAVD88 (2009.55) values to 2007 Low Water Reference Plane … subtract 0.6 ft"), with NAVD88 adjustments that apply only after a date. Those need checking by hand before they're offsets. CWMS's one `LWRP` stage series, at New Orleans, holds only 1936.
- **Gauge zeros that moved:** `GZ` is the gauge zero each value was read against, and at 33 stations, most in MVN, that zero moved partway through the series, typically from NGVD29 to NAVD88. CWMS keeps one series across the reset and says so only in the location's description, so the dates are entered by hand in [`zeros.ts`](zeros.ts), each with the description's words. Venice's zero moved on 2015-06-28, and its hourly stage drops 1.8 ft overnight, matching the 1.84 ft the description gives. Backfill never fetches a value from before a station's date, so each station's files hold one zero and `datums` applies to all of them. The refresh copies the date onto the station as `zero_since`, and keeps the later of that and `zeros.ts`'s, so neither can be dropped on its own; a test fails if a committed date is earlier than `zeros.ts`'s or has no entry there. Each date is also the station's `reference`, so adding one later, or moving one later, opens a new datum epoch (docs/stations.md): the station's values from that date on go to files of their own, and the earlier ones stay in the old epoch's files, outside the combined series until a person says how to convert them. Steele Bayou's landside gauge (`MVK.Steele_Bayou`) has a date too, though its series today ends in July 2017. Left out on purpose: gauges "set to NAVD88" with no date and no earlier zero named (new installations), elevations updated without the zero moving (MVK Helena, MVK Bogalusa), MVN Head of Passes (new gauge set to the old one's water surface), and gauges that moved with no datum noted (several in MVM). Some descriptions also note bad stretches in prose (Reserve's values from 1991-10-04 to 1993-01-14 "are 1 foot too high"), which keep CWMS's flags.
- **Levels:** `timeseries` in SI units, a calendar year per request, following `next-page`. A response with values in anything but meters, or that doesn't say its unit, is refused. Values are UTC epoch milliseconds.
- **Flags:** CWMS quality is a bit field. Missing (4) drops the value, as does a null value; rejected (16) is bad; questionable (8) is suspect; unscreened (bit 0 clear, quality 0) and screened without a verdict (quality 1) are preliminary, since nobody has passed them; a value replaced by linear interpolation (replacement method 1, bits 11 to 14) is interpolated; anything else screened okay is good. The bit layout is USACE's own [CWMS-Data-Quality](https://github.com/USACE-WaterManagement/CWMS-Data-Quality) library's. Some offices screen nothing (St. Louis's series is all quality 0), so all their values are preliminary; MVN screens most of its values.
- **Quality control:** the lake's shared checks run with the outlier rule off (`qc: { outliers: false }` in the source metadata). Navigation pools sit within centimeters for months and then rise meters in a flood, and the rule, which judges a level against the series' own spread, marked Greenup pool's 2024 high water (1,153 values up to 7.42 m) suspect. Limits, spikes and flatlines still apply.
- **Backfill size:** backfill isn't yet bounded by each series' catalog extents, so `backfill usace all` over a long range asks for every year it's given. The daily records reach back to 1861; shard long backfills by station and range.
- **Freshness:** responses whose range ends within the last 120 days, and the catalogs, are never cached, since offices revise recent values. Older years are cached for good, so a later screening pass on them reaches the lake only once the cache is cleared.
