# Environment Agency (`ea`)

Tidal levels every 15 minutes at the Environment Agency's tide gauges, from its [real-time flood-monitoring API](https://environment.data.gov.uk/flood-monitoring/doc/reference): the UK National Tide Gauge Network around Great Britain, Northern Ireland, the Isle of Man and Jersey, which the EA owns, and the EA's own gauges on the English coast.

- **License:** the API is open data under the [Open Government Licence v3.0](https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/), with no registration, and every response's `meta.licence` says so. That allows redistribution and commercial use, so every station goes to the public lake. The EA asks users to acknowledge it with "this uses Environment Agency flood and river level data from the real-time data API (Beta)", which is the attribution. The National Tide Gauge Network's quality-controlled record is BODC's, whose terms need permission for commercial use; this adapter takes only the EA's real-time readings of the same gauges.
- **Stations:** `GET /id/stations?type=TideGauge` lists 84 stations at 43 places. Each National Tide Gauge Network gauge is listed twice, as `E7xx39` in meters above ordnance datum (mAOD) and `E7xx24` in meters above chart datum, and Newport a third time in millimeters; the readings are the same, a constant apart (2.25 m at Aberdeen). The adapter lists each station with a `Tidal Level` measure in mAOD, 39 of them, and the chart datum series of the four gauges that have no mAOD one (Avonmouth, Bournemouth, Hinkley Point and Immingham), 43 in all, by EA notation (`ea/E72239` is Newlyn). It takes only the 15-minute mean series (`-tidal_level-Mean-15_min-`) the archive files are read for, whose ID is the notation, `-level-tidal_level-Mean-15_min-` and the unit (`measureOf`), so a station from `stations.parquet` names its series without the list's extra fields. A chart datum series counts as an mAOD series' twin when it has the same label or lies within about 2 km. A station's page is Check for Flooding's, by its River Levels on the Internet ID, where it has one (12 of 43). Every station is `coastal` and live; country codes are GB but for Jersey (JE) and Port Erin (IM). Jersey's series had no readings at all in November 2026.
- **Datum:** `AOD`, ordnance datum: Newlyn in Great Britain, and the local ordnance datum in Northern Ireland, the Isle of Man and Jersey. `CD`, chart datum, at the four gauges listed by their meters series: the EA labels those series only "m", but where a gauge has both, the meters series is the mAOD one plus the chart datum's depth below ordnance datum (2.25 m at Aberdeen, about 5.8 m at Newport). No offsets between the two are given.
- **Levels:** the series are 15-minute means (`Mean-15_min`), every one `preliminary`, since the EA doesn't quality-control or revise them. `GET /id/measures/<measure>/readings?since=…` answers for the last 30 days or so (from 9 October on 7 November 2026), so the adapter uses it for the last 28 whole days. Days before come from the archive's daily files, `GET /archive/readings-<YYYY-MM-DD>.csv`, which hold every EA measure's readings for the day, about 60 MB each, as `dateTime,measure,value`. The archive keeps about a year (from late October 2025 on 7 November 2026), and a day outside it answers 404. Backfill replaces each month it gets values for, so a month with a day the archive no longer holds (a 404 more than 350 days back, which the run prints) gives no values at all, from the archive or the API, and the lake keeps what it has for that month, as does the month of the split when the API answers with no readings; the archive's first, partial month is never backfilled. A 404 for a day within the last 350 days is a gap in the archive, so it's raised as an error annotation on the run, but it still only drops its month, which the first backfill can't recover. A day file that answers but isn't the CSV, or holds no tide gauge reading, fails the station's year, and is remembered for the run rather than downloaded again by every station. In a range that reaches back past the API's days, the month of the 28-day split also gives nothing when the API's answer is empty or starts more than a day late. While one day file is read, the next three download. A request that starts within the API's 28 days reads no archive file. A value can be blank, or two readings joined by `|`; both are dropped.
- **Archive reading:** a day file is downloaded once a run, never cached on disk (a year of them is about 22 GB), and its tide gauges' readings in meters are kept in memory for the other stations, as flat arrays of numbers, about 3 million readings and 50 MB for a year. Each measure ID is copied into a string of its own, since a substring would keep its whole day file in memory. So a backfill of every station over a year downloads about 365 files, 22 GB, whatever the number of stations; a run on one station costs the same as on all of them, and each shard or rerun downloads them all again, so run it once, unsharded.
- **Clock check:** the readings API's 30 days (`clock-check <30 days ago>/<tomorrow>`, `2026-10-09/2026-11-08` when checked; a range that reaches past them reads 60 MB archive files) fit best at 0 minutes at Newlyn (against UHSLC's record and BODC's), Lowestoft, Dover and Aberdeen (BODC's), with r from 0.88 at Lowestoft to 0.995 at Newlyn. Thirty days don't separate K1, so it shows `no K1`, and the check then fails a lag of 20 minutes or more, where a 12-hour error in a tide this semidiurnal shows; all five are 0.
- **TICON:** the TICON records of these gauges are BODC's and CMEMS's copies of the National Tide Gauge Network, which need permission for commercial use and stay `restricted`. Once the EA's list is in the lake, the inventory matches them by position to the EA's gauge, `ready`, since the EA's readings of the same gauge are open. That record starts with the archive's year, so a fit from it needs the year or more the lake gathers from now on.
- **Limits:** none published. The API's default `_limit` is 500 readings, so the readings request asks for 10,000.

## Backfill

The Monthly workflow refreshes the EA's list on the 2nd with every other source's. The first list has to be in the lake before anything else runs: dispatch Monthly with `sources: ea` once. Until then Ingest hourly and Compact daily skip the EA with a warning, so its readings aren't collected. The archive reaches back only about a year and drops a day each day, so backfill soon after:

```bash
node scripts/ingest.ts backfill ea all 2025 2027
```

Dispatch it with `timeout` at 360. That's two years at each of 43 stations, up to 86 station-years, from about 365 day files, 22 GB in all, downloaded four at a time; the run in November 2026 wrote 82 station-years in about 15 minutes. Without `--first`: every station reads the same day files, so the order saves nothing, and the TICON inventory names no EA station until it has run with the EA's list. From then on Ingest hourly keeps every station's readings, so the lake's record grows from this year on. Run the backfill once: the archive is a copy taken after each day, and the API can deliver readings in batches later, so a later backfill over months hourly ingest has filled could replace them with a copy missing late readings. The EA never finalizes a reading (`finalizes` false), so Monthly's refetch skips `ea`, as it does PEGELONLINE; a gap longer than hourly ingest's 12 hours, such as an Actions outage, stays until someone backfills that stretch, from the API within 28 days or the archive within the year.
