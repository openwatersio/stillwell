# Environment Agency (`ea`)

Tidal levels every 15 minutes at the Environment Agency's tide gauges, from its [real-time flood-monitoring API](https://environment.data.gov.uk/flood-monitoring/doc/reference). The gauges are the UK National Tide Gauge Network around Great Britain, Northern Ireland, the Isle of Man and Jersey, which the EA owns, and the EA's own gauges on the English coast.

- **Stations:** each gauge is `ea/<notation>`, with the EA's station notation (`ea/E72239` is Newlyn). The EA lists each National Tide Gauge Network gauge twice, as `E7xx39` in meters above ordnance datum (mAOD) and `E7xx24` in meters above chart datum, and Newport a third time in millimeters. The readings are the same, a constant apart. The store lists a gauge's mAOD series, or its chart datum series where it has no mAOD one. Avonmouth Portbury, Bournemouth, Hinkley Point and Immingham also have a chart datum series that holds their earlier record, kept in the gauge's group. A station is active while the EA gives its series a latest reading or it has a reading in the last 28 days. Mumbles and Stornoway have never reported and have no values.
- **Levels:** the 15-minute mean series (`Mean-15_min`). A value that is two readings joined by `|` is left out.
- **Times:** UTC. Newlyn's levels fit best at zero lag against UHSLC's and BODC's records of the gauge, and Lowestoft's, Dover's and Aberdeen's against BODC's.
- **Datum:** `AOD`, ordnance datum: Newlyn in Great Britain, and the local ordnance datum in Northern Ireland, the Isle of Man and Jersey. `CD`, Admiralty Chart Datum, for a series in meters above chart datum. The EA labels those series only "m". Where a gauge has both, the chart datum series is the mAOD one plus chart datum's depth below ordnance datum (2.25 m at Aberdeen, about 5.8 m at Newport). The EA gives no offset between the two, so `datums` is empty.
- **Flags:** the API sends no quality code. The EA doesn't quality-control or revise its real-time readings, so every value is `preliminary`.
- **Freshness:** each station's last 12 hours are read every hour. The readings API keeps about 30 days and the EA's daily archive files about a year, so a gap longer than 12 hours stays until it's backfilled from one of them.
- **Gaps:** a day the archive never published has no values unless the poller read it. The store never removes a value it holds, so a span the EA got wrong is flagged by an erratum.
- **Independent checks:** the [pair check](../../../docs/contributing/checks.md#pair-check) on 41 pairs of an EA gauge (39 stations) and another originator's record of it, over the latest year both hold: 39 CMEMS records from the National Oceanography Centre and the regional coastal monitoring programmes, whose RMS is 1.0 cm at the median, and one from CCO. Another 22 pairs, BODC's and the NOC's records of the same gauges, hold the EA's values to the millimeter, so they check nothing. The clocks agree at all 41. EA gauges are in AOD or chart datum, and no other originator's record names either, so the datums are unchecked. The check found the EA's Immingham mAOD series stepping 1.46 m for a day and a half (erratum `ea-immingham-aod-offset`).

## Running ingest

- **Series IDs:** the 15-minute mean series is the one the archive files are read for. Its ID is the notation, `-level-tidal_level-Mean-15_min-` and the unit (`measureOf`), so a station from `stations.parquet` names its series without the list's extra fields.
- **Requests:** `GET /id/measures/<measure>/readings?since=…` serves the last 28 whole days. Days before come from `GET /archive/readings-<YYYY-MM-DD>.csv`, about 60 MB each, as `dateTime,measure,value`, and a day outside the archive answers 404. Backfill keeps every value the store holds and replaces only those at times it fetched (`keepsStored`). The archive is a copy taken after each day, and the API can deliver readings in batches later, so a day's file can lack late readings that the poller kept, and a backfill keeps those. A 404 more than 350 days back is printed; a 404 for a day within the last 350 days is a gap in the archive, so it's raised as an error annotation on the run. A day file that answers but isn't the CSV, or holds no tide gauge reading, fails the station's year, and is remembered for the run rather than downloaded again by every station. While one day file is read, the next three download. A request that starts within the API's 28 days reads no archive file.
- **Archive reading:** a day file is downloaded once a run, never cached on disk (a year of them is about 22 GB), and its tide gauges' readings in meters are kept in memory for the other stations, as flat arrays of numbers, about 3 million readings and 50 MB for a year. So a backfill of every station over a year downloads about 365 files, 22 GB, whatever the number of stations; a run on one station costs the same as on all of them, and each shard or rerun downloads them all again, so run it once, unsharded. The archive answers 429 for a while after a run downloads many day files, as after a full backfill. A refused day file waits 5 minutes, or longer if Retry-After asks, up to 15, holding the other downloads back, and is asked for three times in all (each try retrying a few times over seconds); then the run stops, as for a source that blocks it. A station-year is written only once all its day files are read, so a later run starts those over: run it once the archive has had an hour or more.
- **Station list:** a refresh where no station's series reports fails rather than retire every station. A station that comes back isn't polled until the next refresh lists it active, which the refresh shows only as a changed `status` and `live`. When a refresh shows one going from inactive to active, run `backfill ea <id> <year> <year+1>` over its silent stretch while the archive still holds it (named stations are fetched whatever their status).
- **Clock check:** run it as `clock-check <30 days ago>/<tomorrow>`; a range that reaches past the readings API's 30 days reads 60 MB archive files.
- **Limits:** none published. The API's default `_limit` is 500 readings, so the readings request asks for 10,000.

### Backfill

The Monthly workflow refreshes the EA's list on the 2nd. The poller and Compact daily skip the EA with a warning until the list is in the store, so its readings aren't collected. The archive reaches back only about a year and drops a day each day, so a backfill goes as far back as the archive reaches:

```bash
node scripts/ingest.ts backfill ea all 2025 2027 --with-inactive
```

Dispatch it with `timeout` at 360. `--with-inactive` takes the stations that have stopped too, whose last readings the archive still holds, and the four chart datum series. It's up to two station-years at each of about 47 stations, from about 365 day files, 22 GB in all, downloaded four at a time, and takes about 15 minutes. Without `--first`: every station reads the same day files, so the order saves nothing, and the TICON inventory names no EA station until it has run with the EA's list.

### Scheduled runs

The poller reads each station's last 12 hours. The EA never finalizes a reading (`finalizes` false), so Monthly's refetch skips `ea`. A gap longer than 12 hours, such as an Actions outage, stays until someone backfills that stretch, from the API within 28 days or the archive within the year.
