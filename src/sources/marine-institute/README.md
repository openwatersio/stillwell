# Marine Institute (`marine-institute`)

Sea levels every 5 minutes from the Irish National Tide Gauge Network, run by the Marine Institute with harbor authorities and other partners, from the institute's [ERDDAP](https://erddap.marine.ie/erddap/tabledap/IrishNationalTideGaugeNetwork.html) dataset `IrishNationalTideGaugeNetwork` ("Irish National Tide Gauge Network Real Time Data"): 23 gauges around the coast of Ireland, back to 2006.

- **License:** the dataset's `license` attribute and its [catalogue record](http://data.marine.ie/geonetwork/srv/eng/catalog.search#/metadata/ie.marine.data:dataset.2774) give [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), so every station goes to the public store and is tagged for commercial use. CC BY asks for credit, a link to the license and a note of any changes; the record names no credit line, so attribution is "Marine Institute", the dataset's institution and publisher. The record adds that the Marine Institute accepts no responsibility for errors or for loss from using the data; `terms` carries both. Some gauges sit in harbors run by others, but the dataset serves them all under the same license, and none carries terms of its own.
- **Contact for errors:** data_requests@marine.ie, the publisher address in the [ERDDAP dataset's metadata](https://erddap.marine.ie/erddap/info/IrishNationalTideGaugeNetwork/index.html). The metadata also names a person, whose address the store doesn't carry.
- **Stations:** every `station_id` in the dataset, from `distinct()`. The ID is the network's name for the gauge, such as "Malin Head - Portmore Pier", which isn't URL-safe, so the store's ID is a slug of it, `marine-institute/malin-head-portmore-pier`, and the name is kept as `name`, which the adapter sends back as `station_id`. That name is the only stable identifier the dataset has (`datasourceid`, a number, isn't documented); TICON's `mi_c` records use the same names, such as `malin_head_portmore_pier-mal-irl-mi_c`. A renamed gauge is a station of its own. Where a harbor has two gauges, the network lists them apart ("Galway Port" and "Galway Port 2", "Howth Water Level 1" and "2", "Union Hall Harbor" and "2"), and so does the store. Positions are the dataset's. Each keeps its first and last time as `record_start` and `record_end`, so a backfill asks for nothing outside them. Every station is `coastal`, in Ireland (`IE`), and 5-minute. A gauge with no value for a year is `inactive`; the rest are live. TICON also has `mi_c` records for Arklow Harbour, Fenit and Roonagh Pier, which the dataset no longer serves, so they aren't listed.
- **River gauges:** TICON's `mi_r` records come from a separate dataset, `IrishNationalTideGaugeNetworkRiverGauges` (11 river gauges in Mayo, Dublin and Galway), whose `Water_Level` names no datum and has no QC flag. They aren't listed.
- **Levels:** meters, from `Water_Level_OD_Malin`. Missing values come as null, or with QC flag 9, and are dropped. Sampling starts at irregular minutes in the earliest years and settles on 5-minute marks.
- **Flags:** `QC_Flag` follows the SeaDataNet scheme, documented in the dataset as 0 unknown, 1 good, 9 missing. 1 is a value the institute checked, `good`; 0 is one it hasn't, `preliminary`; 9 is dropped. Any other value is `suspect`; none occur. QC is patchy and well behind: Ballycotton and Malin Head are checked through October 2024, Dublin Port only through February 2019, and some early stretches are unchecked. The dataset documents no flag for bad values.
- **Times:** `time` is UTC.
- **Clock check:** against CMEMS's records of Ballyglass and Sligo (2019) and UHSLC's fast-delivery record of Castletownbere (2020), every series fits best within 10 minutes of zero, and K1's phase puts each within 4 minutes.
- **Datum:** every gauge reports OD Malin, the Irish geodetic datum (`Water_Level_OD_Malin`), and most also report LAT (`Water_Level_LAT`); the second gauges at Galway, Howth and Union Hall report only OD Malin. Levels are stored above OD Malin, as `ODM`. LAT less OD Malin is constant at each gauge from 2008 to 24 March 2026, when the network moved every gauge's LAT by 1 to 5 cm (Ballycotton from 2.489 m to 2.460 m, Dublin from 2.505 m to 2.458 m); OD Malin runs through that day unbroken, so LAT was redefined and OD Malin was not (erratum `marine-institute-lat-2026`). `datums.LAT` is the current offset, read at the gauge's last value on each refresh, so it follows LAT's definition rather than tying the stored levels to one. Kinvara ("Kinvara - Unreferenced") gives values only in the OD Malin column, but the network says the gauge isn't tied to a benchmark, so its datum is `ZERO`. A station is refused values in any datum but the one its name gives.
- **Limits:** ERDDAP publishes none. Requests start at least a second apart, a calendar year per request. A year of one gauge is about 4.5 MB, 560 KB compressed, and takes about 5 seconds (Dublin Port, 2023). A query with no matching rows answers 404 with "Your query produced no matching results" in the body, read as no values; any other 404, such as a renamed dataset, fails. Every gauge's first and last time in one query takes about 60 seconds and hits ERDDAP's gateway timeout, so the station refresh asks each gauge for its own (`orderByMinMax`, up to 7 seconds each), and backfill asks only for the years from a gauge's first day on, and to its last day for one that has stopped.
- **History:** from 2006 (Skerries Harbour) for the oldest gauges, most from 2007 or 2008, the newest from 2024 (Galway Port 2, Buncranna). The dataset's `time_coverage_start` says 2000, but no gauge has values before October 2006 (erratum `marine-institute-coverage-start`).
- **Freshness:** values reach ERDDAP in batches, 10 to 30 minutes after they're measured. The station list and its spans are never cached. A year's response is cached only when every value in it has QC flag 1 and they run to the year's last hour; any unchecked value, or a year still running, is fetched again. An ended year with unchecked values stays preliminary, so Monthly's refetch asks for it again.

## Backfill

The Monthly workflow refreshes the list on the 2nd; Ingest hourly and Compact daily need the list in the store. A full backfill goes through the Ingest workflow:

```bash
node scripts/ingest.ts backfill marine-institute all 2006 2026 --skip-written
```

Without `--first`, since [ticon-replacement.csv](../../../docs/ticon-replacement.csv) names no station of this source until the inventory has run against a store with its list. That's about 300 station-years, each one request of about 5 seconds and 560 KB compressed (about 170 MB in all), so under half an hour: one Ingest run. The current year is fetched whole on every run, so it's backfilled on its own, `backfill marine-institute all 2026 2027`. Ingest hourly brings new values, and Monthly's refetch on the 9th (`backfill marine-institute preliminary`) picks up values the institute has checked since.
