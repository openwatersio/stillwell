# University of Hawaii Sea Level Center (`uhslc`)

Hourly sea level from the University of Hawaii Sea Level Center's [ERDDAP](https://uhslc.soest.hawaii.edu/erddap/): the Joint Archive for Sea Level research-quality data set (RQ, `global_hourly_rqds`) and the fast-delivery data set (FD, `global_hourly_fast`), about 740 series from some 590 gauges worldwide, back to 1846. [UHSLC's notes](https://uhslc.soest.hawaii.edu/datainfo/) describe both.

- **License:** the files say "The data may be used and redistributed for free but is not intended for legal use, since it may contain inaccuracies", with no warranty from the contributor, NOAA or the US government. That lets anyone republish what UHSLC serves, so `redistribution` is true and every station UHSLC serves openly goes to the public store, except those whose contributor refused republication (below). Commercial use is set per station: UHSLC's terms put no limit on purpose, so it's the default, and a station whose contributor attaches terms of its own follows those (below). UHSLC asks users to cite Caldwell, Merrifield and Thompson (2015), [doi:10.7289/V5V40S7W](https://doi.org/10.7289/V5V40S7W), and for FD data the date through which it was obtained; `terms` carries both. Attribution is "University of Hawaii Sea Level Center (UHSLC)", followed by the contributor's credit where its terms ask for one.
- **Contact for errors:** the [contact page](https://uhslc.soest.hawaii.edu/contact/). UHSLC's data metadata names only staff members, whose addresses the store doesn't carry.
- **Contributors:** most of UHSLC's records come from other agencies, and each research-quality record's documentation file (`rqds/<ocean>/doc/qa<id>.dmt`) names its contributor, kept as `contributor` in the store's list. Some files carry the contributor's own terms: BOM's copyright notice (46 records, non-commercial by default), the UK National Tidal and Sea Level Facility's licence at Newlyn, Lerwick and Stornoway (no passing on to third parties, though BODC has confirmed the network's data is under the Open Government Licence, so they're tagged for commercial use), DMI's at Gedser and Hornbæk (non-commercial), SANHO's at Walvis Bay, JMA's (whose current terms are CC BY compatible), the Norwegian Hydrographic Service's (CC BY 4.0) and the National Tidal Facility's (an approved credit line). A file that matches more than one notice takes the strictest, and terms text no notice matches is tagged non-commercial (`unreviewed`) and reported, until a person reads it and adds a notice. All of them are served openly by UHSLC, so all but SANHO's are in the public store; their `commercial_use` follows the contributor's terms, and their attribution adds its credit. The FD series take their RQ version's file, and the 35 or so with no RQ version have no contributor recorded. A version released since the last scan has a file nobody has read, so it's tagged non-commercial, and the refresh says so, until a rescan. [docs/uhslc-contributors.md](../../../docs/uhslc-contributors.md) has the table by contributor, from `node scripts/uhslc-contributors.ts`, which reads every file again (about 720, a second apart) and rewrites [`contributors.ts`](contributors.ts); [`notices.ts`](notices.ts) holds each notice's terms.
- **South Africa:** the South African Navy Hydrographic Office (SANHO) refused permission to republish any of its gauges' data ([#80](https://github.com/openwatersio/stillwell/issues/80)), so its stations are withheld. UHSLC's own download page withholds every station in South Africa until a user accepts SANHO's notice, and the scan has files for only three of them (181A, 184A and 221A, each with SANHO's notice), so the adapter leaves out every station UHSLC lists in South Africa (ISO 3166-1 numeric 710, 11 stations including Marion Island). Walvis Bay, in Namibia, UHSLC serves openly, but its file carries SANHO's notice, which is marked `refused` in [`notices.ts`](notices.ts), so `withheld` names `uhslc/220` and every version of number 220, one the scan hasn't read included, and the adapter never lists or fetches them. Any station number one of whose scanned files carries a `refused` notice is withheld the same way. The rule works from the last scan, so a refusing contributor's record under a station number the scan hasn't read, such as a new gauge, is listed until the scan runs again: run `npm run uhslc:contributors` after each UHSLC release. A rescan that would lose a refusal, because UHSLC reworded the notice or dropped the version that carried it, fails rather than list the station again, unless `--allow-lost-refusal` says a person checked it. Lüderitz (`uhslc/702`), in Namibia, is withheld too, by hand: its file names no contributor, but GESLA names SANHO as originator, and SANHO refused "any of our national tide gauge data", so `ALSO_WITHHELD` in [`notices.ts`](notices.ts) names number 702 with that reason. [CONTRIBUTING.md](../../../CONTRIBUTING.md#withheld-stations) has how withheld stations leave the store.
- **RQ and FD:** RQ data is a station's record after UHSLC's level 2 assessment (datum stability, benchmark ties, comparison with neighbors), released about once a year. A station's record is split into versions, A to E, wherever UHSLC couldn't tie two segments to one benchmark, so each version has a zero of its own. FD data has passed only the level 1 assessment (units, timing, outliers) and arrives 4 to 6 weeks after it's measured. UHSLC's FD files are already one series per station: its latest RQ version, with FD values appended after the last RQ value, and RQ replaces FD as each year's release comes out. Checked at all 294 FD stations with RQ data: the FD series starts on the same day as the station's latest RQ version, and at Pohnpei its 2020 values are identical to version C's.
- **Stations:** so each FD series is a station, `uhslc/<number>` (`uhslc/001`), that carries its station's latest RQ version, and each RQ version it doesn't carry is a station of its own, `uhslc/<number><version>` (`uhslc/001a`, `uhslc/001b`): the older versions, on other benchmarks, and every version of a station with no FD series, such as `uhslc/230a` (Abidjan). A value is stored once, except where the next paragraph's version change leaves the older version in two places. `same_as` links every series with the same station number, and a series whose documentation file names NOS as contributor to its CO-OPS station, and one naming JMA or JODC to its JMA station, by the file's `Originator #` (`originator` in the store's list; JODC's `HD` numbers aren't JMA codes); `stations.parquet` adds links to other originators by nearness and name ([docs/stations.md](../../../docs/stations.md#gauges-in-more-than-one-source)). TICON names records the same way, so its FD record `pohnpei-001-fsm-uhslc_fd` is `uhslc/001` and its RQ record `pohnpei-001a-fsm-uhslc_rq` is `uhslc/001a`; its record of a station's latest version (`pohnpei-001c-fsm-uhslc_rq`) is part of `uhslc/001`, whose `version` (kept in the store's list) says which version that is. Positions are UHSLC's, with longitudes turned from 0–360 to ±180, except six series UHSLC places kilometers from their gauge, Port Stanley's 290A 112 km south of Stanley in the open sea among them, which `POSITIONS` in [src/positions.ts](../../positions.ts) moves to the gauge (erratum `uhslc-positions`); country codes come from UHSLC's ISO numeric codes. Every station is `coastal`, hourly, and not live.
- **Datum:** UHSLC measures every level from its station zero (`reference_datum` "station zero"), named `ZERO` here, and gives no offsets to other datums, so `datums` is empty. A station UHSLC lists against any other reference gets that reference as its datum label, so the refresh opens or holds a datum epoch for it, and its levels are read under that label from then on; a row in any other reference than the station's is refused. A new RQ version under an FD series is a new benchmark: the FD series's `reference` is its RQ version letter, dated a day before the version's first daily value (the daily set can start a day after the hourly record). So when UHSLC moves a series to a new version, the next station refresh opens a datum epoch ([docs/stations.md](../../../docs/stations.md)) from the new version's start and closes the old one there, rather than mixing two zeros in one file. The refresh's report names the opened epoch; Monthly's refetch starts at each station's earliest preliminary value, and the new epoch has none yet, so a person backfills the new version from its first year (`backfill uhslc <number> <first year> <this year>`). The superseded version is then also listed as its own station, `uhslc/<number><version>`, so its values sit in that station and in the series's first epoch, and the series keeps the strictest terms and every credit its versions have carried. The same happens if UHSLC drops a station from the FD set: the FD series goes inactive and its latest version is listed on its own.
- **Levels:** millimeters, as meters. Missing hours come as null and are dropped.
- **Flags:** ERDDAP's `quality` is 4 for RQ values, which are `good`, and 3 for FD values, which are `preliminary`. UHSLC documents no other values, so any other is `suspect`.
- **Hong Kong:** UHSLC stamps its Hong Kong hourly heights (Quarry Bay, station 329, both RQ versions and the FD series) an hour early: the height labeled T was measured at T + 1 h UTC, as tide-database found against the Hong Kong Observatory's predictions. The adapter moves those times an hour later (`EARLY_HOURS`) and asks for the hour before. Take it out once UHSLC corrects its files: the clock check below shows −60 min for UHSLC's times as they are and 0 with the correction, and would show +60 with the correction once UHSLC's times are right.
- **Clock check:** `scripts/clock-check.ts` cross-correlates a year of a series against a TICON record's prediction at 10-minute lags. On 2020 (2015 for the two Taiwanese gauges, and 1980 and 1970 for `uhslc/329a` and `uhslc/001a`), every series checked fits best within 10 minutes of zero against UHSLC's own TICON records: Pohnpei, Honolulu, Wellington, Port Louis, Fremantle, Hong Kong, Kaohsiung, Keelung, Abashiri, Lautoka and Vardø. Those constants were fitted to these records, so they only show a clock that changed since; against other originators' TICON records for the same gauges (BOM at Pohnpei, Fremantle and Lautoka, NOAA at Honolulu, Toitū Te Whenua at Wellington, JCG at Naze, Kartverket at Vardø), every one fits within 10 minutes too. Hong Kong's uncorrected times fit best at −60 min. K1's phase, which a 12-hour error would move by 180°, puts all ten gauges checked against an independent record or Hong Kong's re-fit within 22 minutes, Wellington and Lautoka (UTC+12) included.
- **Limits:** ERDDAP publishes none. Requests start at least a second apart. A year of one station is about 300 KB and takes 1 to 4 seconds. A query with no matching rows answers 404 with "Your query produced no matching results" in the body, which is read as no values; any other 404, such as a renamed dataset, fails. The hourly RQ set can't give every series's first and last time within ERDDAP's 60-second gateway timeout, so the station refresh takes them from the daily sets (`global_daily_rqds`, `global_daily_fast`), and backfill asks only for the years from a month before a station's first day to a month after its last. An FD series still reporting has no last day (`record_end` is empty), since it would change on every refresh; one that has stopped for a year keeps its last day. An FD series carries the RQ version it starts with, which is the latest except while the FD set and the RQ sets reload apart after a release; then it stays on the version before, and the new one is listed on its own until the FD series carries it, so its epoch never fills with the old zero's values. With no version matching, as when ERDDAP mid-reload leaves a row out, the station keeps the version the store's list has. A list that looks caught mid-reload stops the refresh, which keeps the previous list: a version with no daily span (an undated version would open its epoch at the refresh rather than at its start), more than five daily records with no hourly series (the daily set has one, 391A), or more than five FD series gone at once. A real clean-up that large needs `FD_STOPPED` raised for one refresh.
- **Freshness:** the station lists are never cached. Only an RQ version's responses are cached (`uhslc/<number><version>`), and only when every value is RQ and the year runs to its last hour, or to the version's last day. The FD series's responses never are: FD values change, and a new RQ version replaces even its RQ years under the same URL. A version's year cut at its last day is asked for with that day in the URL, so a release that extends it is fetched anew. UHSLC can still reissue a version's values in place. An ended year that holds only RQ values counts as complete, so neither backfill nor the refetch asks for it again; a reissue reaches the store only through `backfill --refetch` (and, locally, a cleared `.cache/`).

## Backfill

The Monthly workflow refreshes UHSLC's list on the 2nd with every other source's. The first list has to be in the store before anything else runs: dispatch Monthly with `sources: uhslc` once, or Compact daily and the refetch fail with no list, and `npm run ticon:inventory` can't read one. Backfill runs through the Ingest workflow, or locally against a local store:

```bash
node scripts/ingest.ts backfill uhslc all 1846 2026 --skip-written --first docs/ticon-replacement.csv
```

That's about 21,000 station-years, at least six hours at one request a second, so it takes two or more Ingest runs, each resuming where `--skip-written` finds the last one stopped. Years outside each station's record aren't asked for. It ends before the current year, which is fetched whole on every run and so is backfilled on its own, `backfill uhslc all 2026 2027`. From then on, Monthly's refetch on the 9th (`backfill uhslc preliminary`) fetches each station from its earliest preliminary value, which brings new FD values and replaces FD with RQ as UHSLC releases it; a station with none is skipped. UHSLC isn't in Ingest hourly, since none of its series is live, but Compact daily runs it so each station's first and last values reach `stations.parquet` after a backfill.
