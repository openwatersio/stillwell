# University of Hawaii Sea Level Center (`uhslc`)

Hourly sea levels from tide gauges worldwide, read from the University of Hawaii Sea Level Center's [ERDDAP](https://uhslc.soest.hawaii.edu/erddap/). UHSLC serves two sets, which [its notes](https://uhslc.soest.hawaii.edu/datainfo/) describe. The research-quality set (RQ, `global_hourly_rqds`) has passed UHSLC's level 2 assessment of datum stability, benchmark ties and agreement with neighbors, and UHSLC releases it about once a year. The fast-delivery set (FD, `global_hourly_fast`) has passed only the level 1 assessment of units, timing and outliers.

- **Stations:** UHSLC splits a gauge's research-quality record into versions, A to E, wherever it couldn't tie two segments to one benchmark. Each FD series is a station, `uhslc/<number>` (`uhslc/001`): the gauge's latest RQ version with FD values appended after its last RQ value. Each RQ version the FD series doesn't carry is a station of its own, `uhslc/<number><version>` (`uhslc/001a`): the older versions, and every version of a gauge with no FD series. `version` in the store's list says which version an FD series carries. Positions and names are UHSLC's.
- **Contributors:** most records come from other agencies. Each RQ version's documentation file (`rqds/<ocean>/doc/qa<id>.dmt`) names its contributor, kept as `contributor` in the store's list, and some carry the contributor's own terms. A station's `commercial_use` follows those terms and its attribution adds the contributor's credit, as [contributors.md](contributors.md) lists by contributor. A file that matches more than one notice in [`notices.ts`](notices.ts) takes the strictest. Terms no notice covers are tagged non-commercial (`unreviewed`) until a notice is added for them, and so is a version released since the last scan of the files, until a rescan reads it. An FD series takes its RQ versions' terms, and one with no RQ version has no contributor and UHSLC's terms alone.
- **Withheld:** the South African Navy Hydrographic Office (SANHO) refused permission to republish any of its gauges' data ([#80](https://github.com/openwatersio/stillwell/issues/80)), so the store leaves out every station UHSLC lists in South Africa, Marion Island included, which UHSLC itself serves only to users who accept SANHO's notice. It also leaves out every series of a station number one of whose files carries a notice marked `refused`, such as SANHO's at Walvis Bay (220) in Namibia, and Lüderitz (702), whose file names no contributor but which GESLA credits to SANHO.
- **Levels:** one an hour, above station zero.
- **Times:** UTC. The clock check fits seven gauges within 10 minutes of zero against other originators' TICON records of them: BOM's at Pohnpei, Fremantle and Lautoka, NOAA's at Honolulu, LINZ's at Wellington, JCG's at Naze and Kartverket's at Vardø. K1's phase puts ten gauges within 22 minutes, which rules out a 12-hour error there, Wellington and Lautoka (UTC+12) included.
- **Datum:** `ZERO`, UHSLC's station zero. UHSLC gives no offsets to other datums, so `datums` is empty. Each RQ version has a zero of its own, so when UHSLC moves an FD series to a new version, the next refresh opens a datum epoch from the new version's start, and the superseded version is listed as its own station as well. The FD series keeps the strictest terms and every credit of the versions it has carried. When UHSLC drops a gauge from the FD set, its FD series goes inactive and its latest version is listed on its own. A station UHSLC lists against another reference takes that reference as its datum label, in an epoch of its own.
- **Flags:** RQ values (ERDDAP's `quality` 4) are `good`, and FD values (3) are `preliminary`. UHSLC documents no other values, so any other is `suspect`. FD values are replaced by RQ values as UHSLC releases each year.
- **Freshness:** FD values arrive 4 to 6 weeks after they're measured, so no station is polled hourly. Monthly's refetch reads each station from its earliest preliminary value to the end of the last year the store holds for it, which brings in RQ releases and new FD values within that year.

## Known limits

- **Later years:** FD values in a year after the last one the store holds for a station reach the store only through a backfill.
- **Reissues:** UHSLC can reissue a version's values in place. A year that holds only RQ values isn't read again once it has ended, so such a reissue doesn't reach the store on its own.
- **Unscanned versions:** the withheld rule works from the last scan of the documentation files, so a refusing contributor's record under a station number the scan hasn't read, such as a new gauge, is listed until the next scan.

## Running ingest

- **Contributor scan:** `node scripts/uhslc-contributors.ts` reads every documentation file again (about 720, a second apart) and rewrites [`contributors.ts`](contributors.ts) and the table in [contributors.md](contributors.md). Run it (`npm run uhslc:contributors`) after each UHSLC release. A rescan that would lose a refusal, because UHSLC reworded the notice or dropped the version that carried it, fails rather than list the station again, unless `--allow-lost-refusal` says the loss was checked. [Withheld stations](../../../docs/contributing/sources.md#withheld-stations) has how withheld stations leave the store.
- **New RQ version:** the refresh's report names the opened epoch. Monthly's refetch starts at each station's earliest preliminary value, and the new epoch has none yet, so the new version needs a backfill from its first year (`backfill uhslc <number> <first year> <this year>`).
- **Limits:** ERDDAP publishes none. Requests start at least a second apart. A year of one station is about 300 KB and takes 1 to 4 seconds. A query with no matching rows answers 404 with "Your query produced no matching results" in the body, which is read as no values; any other 404, such as a renamed dataset, fails. The hourly RQ set can't give every series's first and last time within ERDDAP's 60-second gateway timeout, so the station refresh takes them from the daily sets (`global_daily_rqds`, `global_daily_fast`), and backfill asks only for the years from a month before a station's first day to a month after its last.
- **Mid-reload:** a list that looks caught mid-reload stops the refresh, which keeps the previous list: a version with no daily span, more than five daily records with no hourly series, or more than five FD series gone at once. A real clean-up that large needs `FD_STOPPED` raised for one refresh.
- **Cache:** the station lists are never cached. Only an RQ version's responses are cached, and only when every value is RQ and the year runs to its last hour, or to the version's last day. The FD series's responses never are. An ended year that holds only RQ values counts as complete, so neither backfill nor the refetch asks for it again; a reissue reaches the store only through `backfill --refetch` (and, locally, a cleared `.cache/`).

### Backfill

The first list has to be in the store before anything else runs: dispatch Monthly with `sources: uhslc` once, or Compact daily and the refetch fail with no list, and `npm run ticon:inventory` can't read one. Backfill runs through the Ingest workflow, or locally against a local store:

```bash
node scripts/ingest.ts backfill uhslc all 1846 2026 --skip-written --first docs/ticon-inventory.csv
```

That's about 21,000 station-years, at least six hours at one request a second, so it takes two or more Ingest runs, each resuming where `--skip-written` finds the last one stopped. Years outside each station's record aren't asked for. It ends before the current year, which is fetched whole on every run and so is backfilled on its own, `backfill uhslc all 2026 2027`.

### Scheduled runs

Monthly refreshes UHSLC's list on the 2nd with every other source's. Its refetch on the 9th (`backfill uhslc preliminary`) fetches each station from its earliest preliminary value; a station with none is skipped. The poller doesn't read UHSLC, since none of its series is live, but Compact daily runs it so each station's first and last values reach `stations.parquet` after a backfill.
