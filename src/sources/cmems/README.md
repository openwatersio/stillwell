# Copernicus Marine (`cmems`)

Sea level at tide gauges that Copernicus Marine's In Situ Thematic Assembly Centre (TAC) collects from about 65 national networks and institutes, from the global near-real-time product [INSITU_GLO_PHYBGCWAV_DISCRETE_MYNRT_013_030](https://data.marine.copernicus.eu/product/INSITU_GLO_PHYBGCWAV_DISCRETE_MYNRT_013_030/description) (DOI [10.48670/moi-00036](https://doi.org/10.48670/moi-00036)): about 790 gauges, most in Europe's seas and SHOM's network worldwide, about 600 of them reporting, some back to 1821. Most of them are relays of networks the store also reads directly (RWS, PEGELONLINE, REFMAR, SMHI, DMI, the EA, the Marine Institute, Kartverket); the rest, in Spain, Italy, Greece, Turkey, Estonia, Finland, the Black Sea and elsewhere, have no other open feed.

- **License:** the [Copernicus Marine Service licence](https://marine.copernicus.eu/user-corner/service-commitments-and-licence). Section 2.2 grants a free, worldwide, perpetual licence to redistribute the products in their original form "via any media" and to make derived products "for any purpose", so every station goes to the public store and is tagged for commercial use. Section 2.4 asks for the credit "E.U. Copernicus Marine Service Information" with the product's DOI, which is the source's attribution, and section 2.6 asks licensees to keep records of their use and pass that on, which `terms` says. Every tide-gauge file's `license` attribute names that licence; every gauge's newest file names it, and the refresh fails on a file that names another licence or none. Some files add a credit line of their own in `citation` (SHOM's REFMAR DOI for French gauges, the Open Government Licence for England's regional coastal monitoring gauges, DL-DE Zero 2.0 for BfG's delayed-mode German data); none restricts republishing or commercial use. Each station's `attribution` is the Copernicus credit, the provider's `institution` and that line, and the line is also kept on its own as `citation`. GESLA labels its CMEMS records research-only, a term of GESLA's own compilation that doesn't bind data taken from Copernicus directly.
- **Contact for errors:** Copernicus Marine's [contact page](https://marine.copernicus.eu/contact), which reaches its user support. Each file also names the TAC production unit that made it (`publisher_email`, such as SMHI's for the Baltic), and the provider in `institution`.
- **Access:** no account. The product's files are in the Marine Data Store's public buckets on CloudFerro's S3, readable anonymously. The native files are netCDF-4 (HDF5), which nothing in the store reads, so levels come from the store's ARCO copy instead: one SQLite file per platform, variable and time chunk (`platformChunked`), with `time` (Unix seconds), `value` and `value_qc` columns, which Node reads with its built-in `node:sqlite`. Where the chunks are and how long each spans come from each dataset's STAC record, read once a run. A chunk that doesn't exist, a span with no values, answers 403, so a bucket that moved or locked reads as no values; the weekly canary, which needs values from both datasets, is what notices. Twelve inactive gauges in the native index have no ARCO chunks at all, so the store has no CMEMS levels for them. Eleven are SHOM's (`BaieDuLazaretTG`, `LifouTG`, `LorientTG`, `MataUtuTG`, `OuveaTG`, `PapeeteUhslcTG`, `PariacaboTG`, `PointeDesRochesTG`, `PorquerollesTG`, `PortCrosTG`, `PortDeLaRedonneTG`), each linked to its [REFMAR](../refmar/README.md) series, which is preferred and has the levels. The twelfth is Emercit's Parus (`073`), which only the native file holds ([#443](https://github.com/openwatersio/stillwell/issues/443)). Neither bucket publishes a rate limit; requests aren't paced.
- **Stations:** every tide-gauge file (`TG`) with sea level (`SLEV`) in the native `index_history.txt` and `index_latest.txt`, by platform code, the file name between `<region>_TS_TG_` and its date. SHOM splits a gauge's history by sampling interval (`BrestTG_01minute`, `BrestTG_60minute`), and the store lists the gauge once, as its ARCO copy does (`BrestTG`). The ID is the platform code, which is URL-safe, and GESLA's CMEMS records are named for the same codes. The name is the file's `platform_name`, or the code where that's empty, or where a Baltic file's name has letters beyond ASCII: the Baltic production unit cuts such names short or puts U+FFFD in a letter's place ("Fåbor" for Fåborg, "Ark�" for Arkö; erratum `cmems-baltic-names`). A gauge with a file in the latest window is `active`; the rest are `inactive`, with `record_end` the history's last day. `record_start` is the history's first day. Positions are the newest file's. Nothing is listed `live`, since the hourly job doesn't poll the source. Moorings and buoys that also report sea level (ten `MO` files) aren't listed. The attributes a station keeps (`sea_level_datum`, `platform_name`, `citation`) are read from its newest file: the latest daily file, about 50 KB, or for an inactive gauge its history file, up to 20 MB. A stopped gauge the store's list already has, with the same last day, keeps what the list has and isn't read again. A file that can't be read, such as a daily file that left the window after the index was read, keeps what the list had, or leaves the name to the code and the datum text empty. An empty index refuses the refresh, as does a latest index with fewer than half the gauges the list has active, since it would retire the rest; a first refresh, with no list or fewer than 20 active gauges, has only the empty-index check. A row with a missing position or a time that doesn't exist refuses the refresh too. A gauge's position is the middle of its newest file's span of positions, which is a point for all but Andratx, whose history file spans about 600 m. netCDF-4 writes each text attribute as its name, a type word, its length and a second word, then the text, which the adapter reads from the file's bytes.
- **Country:** none. The files give only the providing institution's country, which isn't the gauge's for SHOM's overseas gauges or JRC's in the Mediterranean.
- **Levels:** meters. Missing values come as null or with QC flag 9 and are dropped, as is a level outside the store's span of −500 to 9,000 m (`SPAN_M`), which some providers use as a fill value (erratum `cmems-fill-values`). Sampling is the provider's, from one minute (Spain, SHOM) to an hour; some providers' history holds hourly values where their latest window holds minutes (Puertos del Estado's Alcudia).
- **Flags:** `value_qc` follows the Copernicus in situ scheme: 0 no QC (`preliminary`), 1 good, 2 probably good and 5 changed (`good`), 3 probably bad (`suspect`), 4 bad (`bad`), 8 interpolated (`interpolated`), 9 missing (dropped); anything else, such as 7 (nominal value), is `suspect`. The TAC's checks are automatic. Values from the latest window are at least `preliminary`, since the history copy replaces them (below). The source checks its values: yes, as the history copy replaces the latest window.
- **Times:** `time` is UTC.
- **Datum:** each provider's own, described in the file's `sea_level_datum` as free text: chart datum, `BSCD2000(DVR90)`, `DHHN2016`, `MSL`, `Harbour Local Datum`, `Unknown`. As with GESLA, levels are stored as `ZERO` and the text is kept as `datum_information`. A gauge whose text changes, other than in case or spacing, has moved its zero, so `seriesChanged` opens an epoch at that refresh. Linked series in the store (`src/links.ts`) give the offsets to the originator's datum where there is one.
- **History and latest:** the product has two datasets. `latest` holds about the last 30 days, updated several times a day, 24 to 48 hours behind. `history` holds each gauge's whole record, updated about monthly, to about two months ago: on 14 November 2026 its ARCO chunks ran to 31 August, updated 21 October, while the latest window began on 15 October. `levels` reads both, asking the latest dataset only for the last 60 days. Where both have a value at a time, the history's stands; the latest window's other values are `preliminary`, including minutes a coarser history lacks. The source keeps stored levels (`keepsStored`): a refetch replaces only the times it fetched, since the latest window moves past the start of a month long before the history copy reaches it. So where a provider's history is coarser than its latest window, as Alcudia's hourly history against its minutes, a month holds both, the minutes the history lacks staying `preliminary`. The history chunks are cached once they end more than a year ago; newer ones and the latest window's are fetched again each time.
- **Freshness:** the source isn't hourly, since values arrive a day or two late and the hourly job reads the last 12 hours. Monthly's refetch on the 9th (`finalizes`) reads every gauge again from six months back to next month, stopped ones included (`backfill cmems all <6 months back> <next month> --with-inactive`), which brings the latest window's new values, replaces the preliminary ones the history copy has reached, and fills the gap between the two datasets once the history covers it. A gauge stops being active about a month after its last value, while the history copy reaches its last months only later, so stopped gauges are read too; one that stopped before the six months asks for nothing.
- **Withdrawn values:** a value the latest window had and the history copy later drops (QC 9, or no value) stays in the store as the latest window gave it, `preliminary`, since the source keeps stored levels.
- **Linking:** CMEMS is a relay, so `src/same-as.ts` marks it redistributed: where it shares a gauge with the originator's series, the originator's is preferred while it reports. GESLA's CMEMS records are linked to it by ID, since GESLA names each record's file for the platform code (`geslaCmems`), as long as the two positions are within 10 km; on 14 November 2026 that linked 700 of GESLA's 717 CMEMS records, and the rest are gauges CMEMS no longer serves or two whose positions differ by 11 and 14 km (Kihnu, Gomera). The copy rule links it to the originator's series (the best-named station of each other source within 2 km), which on 14 November 2026 found one for 480 of the 787 gauges. Its series is preferred over GESLA's, whose CMEMS records aren't tagged for commercial use. Unlike GESLA, it isn't an assembled source: two CMEMS stations are two gauges, and no inferred link joins them in one group. Where CMEMS places a copy beyond 2 km or names it differently, its hourly levels link it in tidal water (the levels rule in [docs/stations.md](../../../docs/stations.md#gauges-in-more-than-one-source)). CMEMS lists three of RWS's gauges twice, under two platform codes with the same values (Den Oever, IJgeul 1, Kornwerderzand); the levels rule links one record of each, and a decision in `LINKS` joins the other. Decisions in `LINKS` also link its copies of RWS's and DMI's gauges on non-tidal water, where the copy rule leaves the match in doubt between equally named stations (Kampen, Krabbersgatsluizen Zuid, Rødby, Roggebotsluis Zuid, Zwartsluis) or misses it because the names share no identifying word (Houtribsluizen Noord and Zuid, Katerveer, Mond der Vecht, Spooldersluis), each with its hourly agreement. The levels rule skips non-tidal stations, so decisions in `LINKS` also link GESLA's records of its copies of FMI's Föglö Degerby and of WSV's Kiel-Holtenau, Rostock and Lübeck gauges on the Baltic, where Lübeck's tide of 9 cm is at the rule's edge, and of PEGELONLINE's Wangerooge West, which a failed sensor's held values can make read non-tidal, as they did until November 2026. CMEMS's copy of PEGELONLINE's Emden gauge holds whole centimeters from July 2025, so it differs from PEGELONLINE's by about half a centimeter RMS a month, within the rule's 1 cm.

## Running ingest

### Backfill

The Monthly workflow refreshes the list on the 2nd. A full backfill goes through the Ingest workflow, inactive gauges included:

```bash
node scripts/ingest.ts backfill cmems all 1821 2027 --skip-written --with-inactive
```

That's about 790 gauges, asked only within each gauge's record, a chunk of 200 days a request, up to about 2 MB each.
